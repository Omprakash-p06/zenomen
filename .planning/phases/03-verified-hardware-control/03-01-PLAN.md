# Plan 03-01: `zenomen-hw` Service — Formalized D-Bus Contract, Mandatory Polkit & Verified Writes

## Objective
Implement the privileged system daemon `zenomen-hw` providing the `com.zenomen.Hardware1` D-Bus system service. Enforce mandatory polkit authorization (`com.zenomen.hardware.control`) on all mutating methods, a verified sysfs write engine with exponential backoff retry (50ms, 100ms, 200ms) reporting `VerificationFailed` on mismatch, strict input whitelisting, and hardened systemd service configuration (**SVC-01**, **SVC-02**, **SVC-03**, **SVC-04**, **SVC-05**, **COOL-04**, **PWR-04**).

## Context & Design Rules
- Follow [`03-RESEARCH.md`](file:///home/omprakash/Documents/zenomen/.planning/phases/03-verified-hardware-control/03-RESEARCH.md) specifications for service architecture:
  - **D-Bus Framework:** Use `zbus = "5"` (or latest compatible zbus with async / blocking support).
  - **Binary Separation (SVC-01, SVC-02):**
    - The GUI binary `zenomen` runs unprivileged.
    - Privileged operations live exclusively in `src/bin/zenomen-hw.rs`.
  - **Polkit Authorization (SVC-03):**
    - Query `org.freedesktop.PolicyKit1.Authority` for action `com.zenomen.hardware.control` using the caller's unique bus name (`system-bus-name`).
    - Enforce authorization on all mutating methods: `SetFanMode`, `SetPowerProfile`, `ApplyPreset`, `ApplyRgbProfile`, `SetRgbEnabled`.
    - Challenged or cancelled authentication must return `zbus::fdo::Error::AccessDenied`.
  - **Formalized Contract & Whitelist Validation (SVC-04):**
    - Interface: `com.zenomen.Hardware1` at `/com/zenomen/Hardware1`.
    - Methods:
      - `GetCapabilities() -> String` (JSON)
      - `GetFanStatus() -> (String, Vec<u32>)` (mode string and fan RPMs)
      - `SetFanMode(mode: String) -> String` (validated to `"auto"` or `"max"`, rejecting `"manual"` without custom curves)
      - `GetPowerProfiles() -> Vec<String>`
      - `GetPowerProfile() -> String`
      - `SetPowerProfile(profile: String) -> String` (validated against choices)
      - `ApplyPreset(preset: String) -> String` (returns JSON `PresetResult`)
      - `ApplyRgbProfile(profile_json: String) -> String`
      - `SetRgbEnabled(enabled: bool) -> String`
    - Reject any unexpected strings, path components, or command injection attempts with explicit invalid argument errors.
  - **Verified Sysfs Write Engine (COOL-04, PWR-04):**
    - Hardware write algorithm writes target value, sleeps 50ms, reads back, and retries up to 3 times (50ms, 100ms, 200ms).
    - If read-back fails to match target after retries, return `HardwareControlError::VerificationFailed`.
  - **Systemd Sandboxing & Distribution Assets (SVC-05):**
    - `data/dbus/com.zenomen.Hardware1.conf`: D-Bus configuration allowing root to own service and users to call methods.
    - `data/polkit/com.zenomen.hardware.policy`: Polkit action with `auth_admin_keep` default for active console sessions.
    - `data/systemd/zenomen-hw.service`: Sandboxed unit with `ProtectSystem=strict`, `ProtectHome=true`, `ReadOnlyPaths=/`, `ReadWritePaths=/sys/devices/platform/hp-wmi /sys/firmware/acpi`.

## Tasks

### Task 1: Dependencies, Core Types & Hardware Control Error
- Update `Cargo.toml` to include `zbus = "5"` (and async runtime support needed for zbus service).
- In `src/lib.rs`, export `pub mod service;`.
- In `src/service/types.rs`, implement:
  - `FanMode`: Enum `Auto`, `Max`, `Manual(u8)`, `Unknown(String)`. Include helpers `as_sysfs_value(&self) -> Option<&'static str>` (`"2"` for Auto, `"0"` for Max).
  - `PresetResult`: Struct with `preset_name: String`, `power_applied: bool`, `fan_applied: bool`, `partial_success: bool`, `message: String`.
  - `HardwareControlError`: Typed error using `thiserror`:
    - `IoError(String)`
    - `VerificationFailed { target: String, actual: String, retries: usize }`
    - `UnsupportedMode(String)`
    - `PolkitDenied(String)`
    - `InvalidParameter(String)`
    - `InterfaceMissing(String)`

### Task 2: Verified Sysfs Write Engine
- In `src/service/backend.rs`:
  - Implement `HardwareBackend` trait / struct with mockable sysfs root path for testing.
  - Implement `write_and_verify(path: &Path, value: &str, retries: usize, initial_delay: Duration) -> Result<(), HardwareControlError>`.
  - Implement fan mode setter: locates `pwm1_enable` (e.g. `/sys/devices/platform/hp-wmi/hwmon/hwmon*/pwm1_enable`), verifies write.
  - Implement power profile setter: locates `/sys/firmware/acpi/platform_profile`, checks against `/sys/firmware/acpi/platform_profile_choices`, executes `write_and_verify`.
  - Implement preset executor: runs power profile write, then fan mode write, and returns structured `PresetResult`.

### Task 3: Polkit Authorization Verifier
- In `src/service/polkit.rs`:
  - Implement `PolkitAuthority` client using `zbus`.
  - Connect to `org.freedesktop.PolicyKit1` at `/org/freedesktop/PolicyKit1/Authority`.
  - Implement `check_authorization(caller: &str, action_id: &str, allow_user_interaction: bool) -> Result<bool, HardwareControlError>`.
  - Format subject dictionary for `system-bus-name` and handle authorization results (`is_authorized`, `is_challenge`).

### Task 4: Formalized D-Bus Contract & Service Binary
- In `src/service/contract.rs`:
  - Define `HardwareService` struct implementing `#[zbus::interface(name = "com.zenomen.Hardware1")]`.
  - Wire all methods: `get_capabilities`, `get_fan_status`, `set_fan_mode`, `get_power_profiles`, `get_power_profile`, `set_power_profile`, `apply_preset`, `apply_rgb_profile`, `set_rgb_enabled`.
  - In each mutating method, extract sender unique name from `#[zbus(header)] hdr: &zbus::message::Header<'_>`, call `check_authorization`, and dispatch to `HardwareBackend`.
- In `src/bin/zenomen-hw.rs`:
  - Initialize tracing subscriber.
  - Connect to system D-Bus (`zbus::connection::Builder::system()`).
  - Request name `com.zenomen.Hardware1`.
  - Serve incoming requests with graceful shutdown handling.

### Task 5: Sandboxing Configuration & Integration Tests
- Create configuration files in `data/`:
  - `data/dbus/com.zenomen.Hardware1.conf`
  - `data/polkit/com.zenomen.hardware.policy`
  - `data/systemd/zenomen-hw.service`
- In `tests/hardware_service_tests.rs`:
  - Test verified write loop with simulated sysfs files (immediate success, delayed match after retry, persistent mismatch returning `VerificationFailed`).
  - Test `FanMode` validation (Auto and Max succeed; manual "1", arbitrary strings, and path traversal strings fail with `InvalidParameter` or `UnsupportedMode`).
  - Test `PresetResult` partial failure reporting when one write succeeds and another fails.
  - Verify D-Bus and polkit XML/conf files are well-formed.
