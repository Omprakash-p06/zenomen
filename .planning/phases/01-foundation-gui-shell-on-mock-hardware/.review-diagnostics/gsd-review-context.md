# Phase 1 — UI Design Contract

> Visual and interaction contract for the ZenOmen GUI shell. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Phase 1 renders mock hardware data only. Nothing in this contract authorizes a hardware read or write from the UI layer.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — repo-authored Slint tokens (`ui/theme/colors.slint`, `ui/theme/typography.slint`, `ui/theme/metrics.slint`); no component registry, no design-system package |
| Preset | not applicable |
| Component library | Slint 1.17 `std-widgets` (`Button`, `CheckBox`, `ScrollView`, `Slider`, `VerticalBox`, `HorizontalBox`, `GridLayout`) plus repo-authored components in `ui/components/` |
| Icon library | none — hand-authored `Path` glyphs in `ui/components/icons.slint` (20×20 box, 2px stroke, single colour bound to the surrounding text token) |
| Font | Inter (400, 600) and JetBrains Mono (400), embedded via `import "./fonts/Inter-Regular.ttf";`-style imports in `ui/theme/typography.slint` |

**Theme scope:** dark only in this phase. Every colour and type value lives in the three `ui/theme/*.slint` files and is referenced by name — no literal hex appears in a screen file. A light theme (SYS-08, Phase 4) will be a second token file, not a second set of screens.

**Slint facts this contract depends on** (verified 2026-10-30 against docs.slint.dev):
- A font is embedded by importing the `.ttf` in a `.slint` file; the family then resolves through `font-family` application-wide.
- `FocusScope` provides `focus-on-tab-navigation`, `key-pressed(event)`, `focus-changed-event(reason)` and `focus()`/`clear-focus()`; tab traversal follows declaration order.
- Non-printable keys map into the `Key` namespace (`Key.Return`, `Key.Space`, `Key.Escape`, `Key.Up`, `Key.Down`).
- `Path` accepts SVG path-data in `commands`, which is how charts are drawn (see Chart rendering below).

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between a numeric value and its unit; icon-to-label gap |
| sm | 8px | Compact stack spacing inside a card; pill padding |
| md | 16px | Card padding; grid gap between metric cards; card-internal row spacing |
| lg | 24px | Page padding; gap between card grid and chart; header horizontal padding |
| xl | 32px | Gap between major blocks (hero row → chart → footer) |
| 2xl | 48px | Reserved for empty-state and notice vertical breathing room |
| 3xl | 64px | Page-level top offset when a screen has no header action |

Exceptions (structural dimensions, all multiples of 4 — none are ad-hoc spacing):

| Value | Purpose |
|-------|---------|
| 200px | Sidebar width, fixed at every window size |
| 64px | Header height |
| 40px | Status strip height; minimum height of a sidebar nav row and of any interactive target |
| 220px | Minimum metric-card width (drives the responsive column count below) |
| 28px | Sparkline height |
| 160px | Telemetry chart plot height |
| 1px / 2px | Stroke widths: 1px outlines and grid lines, 2px focus ring and chart strokes. Stroke widths are not spacing tokens |

Responsive column count for the Overview card grid (content width = window width − 200px sidebar − 48px page padding, gap 16px):

| Content width | Columns |
|---------------|---------|
| ≥ 928px | 4 |
| ≥ 692px | 3 |
| ≥ 456px | 2 |
| < 456px | 1 |

Default window 1180×760, minimum 940×620 — at the default the 4-column rule applies, at the minimum the 3-column rule applies.

## Typography

Exactly four sizes, exactly two weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12px | 400 | 1.4 |
| Heading | 20px | 600 | 1.25 |
| Display | 32px | 600 | 1.2 |

| Rule | Value |
|------|-------|
| Families | Inter for all prose; JetBrains Mono for every numeric readout (values, RPM, watts, °C, percentages, version strings) |
| Mono sizes | JetBrains Mono at Display (32px) and Heading (20px) only — never at Body or Label |
| Numeric alignment | Tabular figures; values left-aligned in cards so digits line up down a column |
| Label treatment | 12px, uppercase, letter-spacing 0.04em, `text-secondary` — used for card labels, units and table headers |
| Weight usage | 600 only for Display, Heading and the active sidebar row label; 400 everywhere else. No 300/500/700/800 in this phase |

## Color

Dark theme. 60/30/10 split declared explicitly.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0B0C0F` Obsidian | Window background, content gutters, chart plot background |
| Secondary (30%) | `#15171C` Charcoal | Sidebar, metric cards, section cards, chart wells |
| Raised surface | `#1B1E25` Slate | Inline notices, hover state, nested rows inside a card |
| Outline | `#262A33` Graphite | 1px card/section borders and chart grid lines; never used for text |
| Text primary | `#E8E6E3` | Values, headings, active nav label |
| Text secondary | `#9BA1AC` | Labels, units, helper text, inactive nav rows |
| Accent (10%) | `#C6A15B` Muted gold | See reserved list below — and nothing else |
| Alert / Destructive | `#E0606B` Crimson | Alert text, alert glyphs, alert borders, destructive confirmation fill |

Measured contrast (WCAG 2.1, computed 2026-10-30): text-primary 15.7:1 on Obsidian and 14.4:1 on Charcoal; text-secondary 7.5:1 / 6.9:1; gold 8.1:1 / 7.4:1; crimson 5.6:1 / 5.2:1 and 4.8:1 on Slate. Obsidian text on a gold fill measures 8.1:1. Every text/background pair this contract names clears 4.5:1.

**Accent reserved for — this is the complete list:**

1. The active sidebar row: label at weight 600 plus a 2px left rail.
2. The keyboard focus ring: 2px, 2px offset, drawn outside the focused element.
3. The primary action button fill, with Obsidian label text (`Refresh Telemetry` in Phase 1).
4. The selected option in a segmented/radio group (fan mode, power profile — declared now, used from Phase 3).
5. The primary chart series stroke (CPU utilization) and its legend swatch.
6. The static Enso mark in the sidebar header and the "ZenOmen" wordmark.
7. The Mock-data badge outline and label.

Everything else is neutral: secondary buttons use an Outline border with text-secondary; inactive nav rows are text-secondary; chart grid lines are Outline; non-primary chart series are the two neutral tints below. A control that is merely hovered or merely enabled gets no accent.

**Chart series palette** — one accent plus two neutral tints, never an extra hue:

| Series | Value |
|--------|-------|
| CPU utilization | `#C6A15B` (accent) |
| GPU utilization | `#9BA1AC` (text-secondary) |
| RAM usage | `#5D6470` (neutral tint) |
| Grid lines | `#262A33` (Outline), 1px, three lines at 0/50/100% |

**Alert semantics — colour is never the only signal:**

| Condition | Treatment |
|-----------|-----------|
| Temperature < 85°C | text-primary value, no glyph, no pill |
| Temperature ≥ 85°C | crimson value + `warning` glyph + label "Elevated" |
| Temperature ≥ 95°C | crimson value + filled crimson `StatusPill` reading "Critical" |
| Sensor absent / capability missing | text-secondary value "Unavailable" + `unavailable` glyph + `StatusPill` reading "Unavailable" |
| Service or provider degraded | `StatusStrip` with gold outline + `warning` glyph + the reason in text |

No gradients, no drop shadows, no blur, no animated shimmer in Phase 1. Elevation is conveyed by surface step plus a 1px Outline.

## Visual Hierarchy

**Window.** OS window title is `ZenOmen`; no custom title bar and no client-side decorations in this phase.

**Shell layout.** A fixed 200px Charcoal sidebar holds the Enso mark, the wordmark and six nav rows; a 64px header holds the screen title and the primary action; a 40px `StatusStrip` spans the content area directly under the header; the content area scrolls (`ScrollView`) with 24px padding. Sidebar and header stay fixed while content scrolls.

**Primary visual anchor by screen** — the executor must make this element the most prominent thing on the screen:

| Screen | Anchor |
|--------|--------|
| Overview | The CPU metric card's Display value (32px mono) — largest type on the page |
| Cooling | The per-fan RPM readout list, each row a Heading-size mono value |
| Performance | The current power profile name at Heading size, with the advertised list beneath it |
| Lighting | The RGB support state pill plus the active profile name |
| Settings | The About block (version, build, provider mode) |
| Diagnostics | The capability summary table |

**Reading order** in every screen: title → status strip → primary anchor → supporting cards → chart or detail table. The wide TelemetryChart is the secondary anchor on Overview — it never competes with the CPU value, so it stays monochrome-plus-accent and unlabelled on the plot itself (values live in the legend and cards).

**Scan pattern:** all six screens use the same top-left-to-bottom-right flow with a 16px grid; there is no centred hero, no card carousel and no lateral scrolling anywhere.

## Keyboard & Interaction Contract

| Input | Behaviour |
|-------|-----------|
| `Tab` / `Shift+Tab` | Move focus in declaration order: sidebar rows → header action → screen controls → chart. Implemented with `FocusScope { focus-on-tab-navigation: true; }` |
| `Up` / `Down` (sidebar focused) | Move between nav rows via `key-pressed` on the sidebar's `FocusScope`; `accept` the event so it does not scroll the content |
| `Return` / `Space` | Activate the focused nav row or button |
| `Escape` | Clear focus from the chart and any transient notice; returns focus to the sidebar's active row |
| Mouse click | Same effect as `Return` on the same element — every click target is also a tab stop |

**Interaction states — declared so none is invented during implementation:**

| State | Treatment |
|-------|-----------|
| Default | Card at Charcoal, 1px Outline border, text-primary value, text-secondary label |
| Hover | Surface steps to Slate `#1B1E25`; border unchanged; no accent appears |
| Focused | 2px gold ring, 2px offset, outside the element; no surface change |
| Pressed | Surface stays Slate, border switches to text-secondary; value does not move or scale |
| Selected (nav row / segment) | Gold left rail 2px + weight 600 label; surface unchanged |
| Unavailable | `UnavailablePanel` replaces the control's body — there is no disabled-but-present control in Phase 1, so no unreadable greyed-out state exists to style |

`ScrollView` scrollbars: 8px wide, Outline track, text-secondary thumb, no arrows, no auto-hide animation.

Rules:
- A control that cannot act in this phase is replaced by a `CapabilityNotice` or `UnavailablePanel`, never a tooltip alone and never a disabled-looking button.
- The focus ring is the only thing that may be gold on a merely focused element; a focused-but-inactive nav row shows the ring without the active rail.
- Every icon-only control carries `accessible-label` naming the action (Slint `accessible-*` properties); no icon-only control is unlabelled.
- No control changes state on hover or on scroll; no auto-advancing carousel, no timed toast that removes information — a notice stays until the condition that produced it clears.
- Screen changes are instant (no transition animation). Charts repaint only when a new snapshot arrives, at the polling cadence — never on a per-frame timer.

## Screen Contracts (Phase 1)

Every screen renders from the mock provider. Where a capability does not exist, the screen uses the "arrives later" notice rather than a dead control, so no panel is ever blank.

| Screen | Phase 1 content | Deliberate placeholder |

| Cooling | Per-fan RPM rows, current fan mode as a read-only `StatusPill` | `CapabilityNotice`: "Fan control arrives with the verified hardware service. This build reads mock fan speed only." |

## Chart rendering

- The core computes every chart path. A pure function in Rust produces SVG path data (`M x y L x y …`) from the bounded history buffer; the `.slint` layer only renders it.
- `Sparkline` is one 2px `Path` on a transparent background, 28px tall, no axes, no labels, no fill.
- `TelemetryChart` is 160px tall, no vertical axes, three 1px horizontal grid lines, 2px series strokes, and a legend row of Label-size items below the plot.
- A series with fewer than two samples renders the "Waiting for first reading" copy instead of a flat line at zero — zero would be indistinguishable from a real reading.
- A metric card whose sensor is unavailable renders no sparkline at all: an empty trace would imply a history that does not exist.
- The chart keeps a fixed plot height so a new snapshot never reflows the page (a reflow while frames are being measured makes the PERF-03 frame-time criterion meaningless).

## Data & Text States

| Situation | Contract |
|-----------|-----------|
| Text longer than its slot (card label, nav row, legend entry, table cell) | One line with a trailing ellipsis; the full string is carried in `accessible-label`. Layout height never changes with text length |
| Numeric value longer than its slot (e.g. `16384 MB` at Display size) | The value never truncates and never shrinks its type size: the unit drops to its own line beneath the number |
| A sensor reports, then goes missing for some ticks | The trace breaks and resumes; the series and its legend entry stay; the card's `StatusPill` reads `Unavailable` for exactly the missing ticks |
| A snapshot carries only some sensors | The affected card keeps its grid slot and renders the unavailable state in place — grid geometry is identical to the fully-populated case |
| Fewer than two samples for a series | `Waiting for first reading` in place of the trace; never a flat line at zero |
| History shorter than the configured window | Plot what exists, right-aligned to "now"; never pad the left edge with a fabricated zero |
| More rows than the viewport (fan list, capability table, card grid) | The content area scrolls as one surface at 24px padding. No pagination, no nested scroll region inside the card grid |
| One fan, or six fans | Same row shape, full width; the count changes the number of rows and nothing else — no special single-item layout |
| Zero fans / zero rows in a table | The card or table body renders `Unavailable` plus the reason; the card is not removed |
| Window at minimum size (940×620) | Four-column grid steps to three columns; nothing is hidden, clipped or reordered |

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Refresh Telemetry` |
| Secondary action | `View Diagnostics` (status strip, when it reports a problem) |
| Status strip, nominal | `Mock provider · 12 of 12 sensors reported` |
| Status strip, partial | `Mock provider · 9 of 12 sensors reported — View Diagnostics` |
| Empty state heading | `Waiting for first reading` |
| Empty state body | `No telemetry snapshot has arrived yet. One is published every polling interval — select Refresh Telemetry to sample now.` |
| Error state | `Couldn't read telemetry: {reason}. The monitoring worker retries every 5 seconds; the rest of this screen is unaffected.` |
| Unavailable sensor | `Unavailable` (value slot) + `{Component} {metric} sensor not found on this machine.` + `Open Diagnostics to see which sensors were detected.` |
| Unsupported subsystem | `{Subsystem} isn't available on this machine` + one sentence naming the interface that is missing, e.g. `hp-wmi exposes no writable pwm1_enable here.` |
| Mock data badge | `Mock data — no hardware is being read` |
| Service unreachable (later phases, declared now) | `Hardware service unreachable` + `Telemetry still works. Controls are disabled until it reconnects.` |
| Destructive confirmation | None in this phase. Reserved pattern for later phases: `{Verb} {noun}?` as the title, one sentence of consequence, primary button repeats the verb, secondary reads `Keep {noun}`. |

**Copy rules:**
- Never write `0`, `N/A`, `--` or a blank where a sensor is missing — the value slot reads `Unavailable` and the reason appears in the same card.
- Never write `Error` or `Something went wrong` alone; every error names the cause and the next step.
- Every placeholder notice names the phase that replaces it, so a tester reading the screen knows the gap is deliberate.
- Labels are sentence case (`Fan speed`, not `FAN SPEED`); the Label-size uppercase treatment applies to card labels only, through letter-spacing, not through capitalised strings.
- Units are separate text nodes at Label size (`°C`, `W`, `RPM`, `%`), so a unit never shrinks a value's alignment.
