# Plan 06-05: Windows Desktop Integration & UI Architecture

## Objective
Implement native Windows desktop integration functions under `src/desktop/windows/` fulfilling the exact signatures and contracts in Sections 4.3 and 5.3 of the specification. Establish the GPUI-CE cross-platform UI migration scaffold under `src/ui/` with strict domain decoupling, keeping Slint as the verified active presentation layer until dual-OS feature parity is complete.

## Codebase Map References
- `ARCHITECTURE.md`: Desktop integration layer, single instance, system tray, and ADR-001 framework context.
- `STRUCTURE.md`: Module tree under `src/desktop/`.
- `INTEGRATIONS.md`: Releases browser handoff and single-instance activation.

## Detailed Implementation Tasks

### Task 1: Windows Desktop Integration Module Tree
Create `src/desktop/windows/`:
- `mod.rs`: Re-exports desktop integration functions.
- `single_instance.rs`: `acquire_single_instance`, `present_existing_window`.
- `tray.rs`: `register_tray_icon`, `remove_tray_icon`.
- `autostart.rs`: `set_autostart_enabled`.
- `notifications.rs`: `show_notification`.
- `releases.rs`: `open_releases_page`.
- `paths.rs`: `resolve_app_data_paths`.
- `installer.rs`: `install_hardware_service`, `uninstall_hardware_service`.

### Task 2: Single-Instance Mutex & Window Activation (`single_instance.rs`)
Implement:
1. `pub fn acquire_single_instance() -> Result<SingleInstanceResult, DesktopError>`:
   - Creates named session mutex: `Local\\ZenOmen.SingleInstance`.
   - If `GetLastError() == ERROR_ALREADY_EXISTS`:
     Calls `present_existing_window()`, closes handle, and returns `SingleInstanceResult::AlreadyRunning`.
   - If successful, returns `SingleInstanceResult::Primary(handle)`.
2. `pub fn present_existing_window() -> Result<(), DesktopError>`:
   - Calls `FindWindowW(null, "ZenOmen")`.
   - If found: calls `ShowWindow(hwnd, SW_RESTORE)` and `SetForegroundWindow(hwnd)`.

### Task 3: Notification Area Tray & Context Menu (`tray.rs`)
Implement:
1. `pub fn register_tray_icon(action_sender: mpsc::SyncSender<DesktopAction>) -> Result<TrayHandle, DesktopError>`:
   - Registers a hidden Win32 message window (`CreateWindowExW`) with class name `"ZenOmenTrayMsgWindow"`.
   - Populates `NOTIFYICONDATAW` (`cbSize`, `hWnd`, `uID = 1`, `uFlags = NIF_ICON | NIF_MESSAGE | NIF_TIP`, `uCallbackMessage = WM_USER + 1`).
   - Sets tooltip to `"ZenOmen - Hardware Control"`.
   - Calls `Shell_NotifyIconW(NIM_ADD, &nid)`.
2. Window Procedure Callback:
   - On `WM_LBUTTONUP`: Dispatches `DesktopAction::PresentWindow`.
   - On `WM_RBUTTONUP`:
     Calls `CreatePopupMenu()`. Adds items: `"Open ZenOmen"` (default), `"Fan Mode: Auto"`, `"Fan Mode: Max"`, separator, `"Quit ZenOmen"`.
     Calls `TrackPopupMenu(...)`. Dispatches selected command to `action_sender`.
3. `pub fn remove_tray_icon(handle: &TrayHandle) -> Result<(), DesktopError>`:
   Calls `Shell_NotifyIconW(NIM_DELETE, &handle.nid)`.

### Task 4: User Autostart via Registry (`autostart.rs`)
Implement:
1. `pub fn set_autostart_enabled(enabled: bool) -> Result<(), DesktopError>`:
   - Opens `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run`.
   - If `enabled == true`: writes value `"ZenOmen"` with string data `"<path_to_zenomen.exe> --minimized"`.
   - If `enabled == false`: calls `RegDeleteValueW(hkey, "ZenOmen")`.
2. `pub fn is_autostart_enabled() -> bool`:
   Queries whether `"ZenOmen"` exists in the Run key.

### Task 5: Browser Opener & Notifications (`releases.rs`, `notifications.rs`)
Implement:
1. `pub fn open_releases_page() -> Result<(), ReleasesError>`:
   Calls `ShellExecuteW(null, "open", "https://github.com/Omprakash-p06/zenomen/releases/latest", null, null, SW_SHOWNORMAL)`.
   Verifies return value > 32.
2. `pub fn show_notification(title: &str, message: &str) -> Result<(), DesktopError>`:
   Uses `Shell_NotifyIconW` with `NIF_INFO` to post balloon / toast notifications.

### Task 6: Application Data & State Paths (`paths.rs`)
Implement:
1. `pub fn resolve_app_data_paths() -> Result<AppDataPaths, DesktopError>`:
   - Calls `SHGetKnownFolderPath(FOLDERID_LocalAppData)` → `%LOCALAPPDATA%\ZenOmen\` (config, user logs, diagnostics).
   - Calls `SHGetKnownFolderPath(FOLDERID_ProgramData)` → `%PROGRAMDATA%\ZenOmen\` (service logs and hardware cache).
   - Creates directories if absent.

### Task 7: GPUI-CE Architecture & Migration Scaffold (`src/ui/`)
Scaffold the UI directory structure specified in Section 5.4:
```text
src/ui/
├── mod.rs
├── app.rs
├── theme/
│   ├── mod.rs
│   ├── colors.rs
│   ├── typography.rs
│   └── spacing.rs
├── components/
│   ├── sidebar.rs
│   ├── metric_card.rs
│   ├── telemetry_chart.rs
│   ├── status_strip.rs
│   ├── action_button.rs
│   └── value_readout.rs
└── screens/
    ├── overview.rs
    ├── cooling.rs
    ├── performance.rs
    ├── lighting.rs
    ├── settings.rs
    └── diagnostics.rs
```
**Parity Contract:** Slint files in `ui/` are retained as the active GUI engine. The `src/ui/` modules establish the GPUI element tree definitions, consuming the identical typed `AppEvent` and `AppCommand` contracts from `src/core/events.rs`.
