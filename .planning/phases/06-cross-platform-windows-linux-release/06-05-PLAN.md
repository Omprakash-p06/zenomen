# Plan 06-05: Windows Desktop Integration, Packaging & Dual-OS CI

## Objective
Implement native Windows desktop integration (notification area system tray, single-instance mutex, user-level autostart, browser opener) and establish an automated dual-platform CI/CD and release pipeline for Linux and Windows 10/11.

## User-Facing Impact
- **Seamless Desktop Presence**: ZenOmen lives in the Windows notification area tray with custom tooltips and context menus. Closing the window minimizes to tray when configured.
- **Single-Instance Protection**: Launching ZenOmen when already running smoothly presents the existing window rather than starting duplicate polling loops.
- **Automated Releases**: Official GitHub releases automatically publish tested Linux `.deb`, `.AppImage`, and Windows `.exe` binaries with cryptographic SHA-256 checksums.

---

## Detailed Implementation Steps

### Step 1: Native Windows Notification Area Tray (`src/desktop/windows/tray.rs`)
1. **Hidden Message Window**:
   Create a lightweight hidden Win32 window (`CreateWindowExW`) with a dedicated `WNDCLASSEXW` to receive tray notification messages (`WM_USER + 1`).
2. **`Shell_NotifyIconW` Lifecycle**:
   - `NIM_ADD`: Register tray icon using `NOTIFYICONDATAW` with flags `NIF_ICON | NIF_MESSAGE | NIF_TIP`.
   - Tooltip: Set `szTip` to `"ZenOmen - Hardware Control"`.
   - Icon: Extract embedded icon from executable resources (`LoadIconW`).
   - `NIM_DELETE`: Cleanly unregister the tray icon when the application shuts down.
3. **Context Menu via `TrackPopupMenu`**:
   On `WM_RBUTTONUP`:
   - Create popup menu via `CreatePopupMenu`.
   - Add items: `"Open ZenOmen"` (default), `"Fan Mode: Auto"`, `"Fan Mode: Max"`, separator, `"Quit ZenOmen"`.
   - Call `SetForegroundWindow(hwnd)`.
   - Call `TrackPopupMenu(hmenu, TPM_RIGHTBUTTON | TPM_RETURNCMD, pt.x, pt.y, 0, hwnd, null)`.
   - Dispatch selected command to `action_sender`.

### Step 2: Single-Instance Mutex & Activation (`src/desktop/windows/single_instance.rs`)
1. **Named Session Mutex**:
   ```rust
   pub fn ensure_single_instance() -> SingleInstanceResult {
       // Local\ scope limits mutex to the current interactive session
       let mutex_name = b"Local\\ZenOmen.SingleInstance\0";
       let handle = unsafe {
           CreateMutexA(std::ptr::null_mut(), FALSE, mutex_name.as_ptr() as *const i8)
       };
       if handle.is_null() {
           return SingleInstanceResult::Disabled("Failed to create mutex".into());
       }
       if unsafe { GetLastError() } == ERROR_ALREADY_EXISTS {
           // Secondary instance: signal primary window to activate
           signal_primary_window();
           unsafe { CloseHandle(handle) };
           return SingleInstanceResult::AlreadyRunning;
       }
       SingleInstanceResult::Primary(handle)
   }
   ```
2. **Window Activation**:
   Find existing window using `FindWindowW(null, "ZenOmen")` and post `WM_USER + 100` (`PresentWindow`) or call `SetForegroundWindow` / `ShowWindow(hwnd, SW_RESTORE)`.

### Step 3: User-Level Autostart (`src/desktop/windows/autostart.rs`)
1. **HKCU Run Registry Key**:
   Target key: `Software\Microsoft\Windows\CurrentVersion\Run`.
   - `enable_autostart(exec_path)`: Call `RegOpenKeyExW(HKEY_CURRENT_USER, ...)` with `KEY_WRITE`. Write value `"ZenOmen"` with data `"<path_to_zenomen.exe> --minimized"`.
   - `disable_autostart()`: Call `RegDeleteValueW(hkey, "ZenOmen")`.
   - `is_autostart_enabled()`: Call `RegQueryValueExW` to verify if the `"ZenOmen"` value exists.
   - Requires zero administrator rights.

### Step 4: Browser Releases Opener (`src/desktop/windows/releases.rs`)
1. **`ShellExecuteW` Implementation**:
   ```rust
   pub fn open_releases_page() -> Result<(), ReleasesError> {
       let url: Vec<u16> = "https://github.com/Omprakash-p06/zenomen/releases/latest\0"
           .encode_utf16()
           .collect();
       let operation: Vec<u16> = "open\0".encode_utf16().collect();
       // SAFETY: ShellExecuteW opens URL in user's default browser
       let res = unsafe {
           ShellExecuteW(
               std::ptr::null_mut(),
               operation.as_ptr(),
               url.as_ptr(),
               std::ptr::null(),
               std::ptr::null(),
               SW_SHOWNORMAL,
           )
       };
       if res as usize <= 32 {
           return Err(ReleasesError::SpawnFailed(format!("ShellExecute error: {res}")));
       }
       Ok(())
   }
   ```

### Step 5: Dual-OS Automated CI Matrix (`.github/workflows/ci.yml`)
1. **Matrix Definition**:
   ```yaml
   jobs:
     quality-gates:
       strategy:
         matrix:
           os: [ubuntu-latest, windows-latest]
       runs-on: ${{ matrix.os }}
       steps:
         - uses: actions/checkout@v4
         - uses: dtolnay/rust-toolchain@stable
           with:
             components: clippy, rustfmt
         - if: matrix.os == 'ubuntu-latest'
           run: |
             sudo apt-get update && sudo apt-get install -y libxkbcommon-dev libfontconfig1-dev libdbus-1-dev xvfb
             cargo fmt --all -- --check
             git diff --check
             cargo clippy --all-targets --all-features -- -D warnings
             xvfb-run -a cargo test --all
             cargo audit
         - if: matrix.os == 'windows-latest'
           run: |
             cargo check --target x86_64-pc-windows-msvc --all-targets --all-features
             cargo clippy --target x86_64-pc-windows-msvc --all-targets --all-features -- -D warnings
             cargo test --target x86_64-pc-windows-msvc --lib
   ```

### Step 6: Automated Dual-OS Release Workflow (`.github/workflows/release.yml`)
1. **Release Build Steps**:
   - Linux Job: Builds `zenomen_*.deb` and `ZenOmen_*.AppImage`.
   - Windows Job: Builds `zenomen.exe` and `zenomen-hw.exe` (`--release`), embedding icon and manifest resources.
   - Consolidated Job: Gathers all artifacts, computes `sha256sum * > SHA256SUMS`, and creates the GitHub Release with attached assets.
