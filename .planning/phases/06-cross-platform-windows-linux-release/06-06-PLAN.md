# Phase 6 — Plan 06-06: Wave 6 — Packaging, Full Testing Matrix, Documentation Deliverables & Final Acceptance Gates

## Goal
Implement and verify the complete cross-platform packaging pipeline (WiX MSI for Windows 10/11, Debian `.deb` and AppImage for Linux), establish the automated and physical CI/CD testing matrix across Linux and Windows 10/11, produce all required architectural ADRs and validation guides, and verify the 14 final acceptance criteria for the unified cross-platform release.

## 1. Target OS & Platform Support Contract

| OS Platform | Target Build / Architecture | Support Tier | Requirements & Hardware Boundaries |
|:---|:---|:---|:---|
| **Windows 10** | 22H2 (Build 19045+, x86_64) | Tier 1 (Full) | Minimum Windows desktop baseline. Uses DXGI 1.3+, PDH, Win32 APIs, WMI `hpqBIntM`, Named Pipe IPC. Runs unprivileged GUI + `LocalSystem` service. |

| **Linux (Generic)** | glibc 2.35+ (x86_64) | Tier 1 (Full) | Self-contained AppImage bundle. Includes desktop launcher, multi-resolution SVG/PNG icons, D-Bus client fallback. |

### 2.2 Windows Application Resources (`build.rs` & `winres`)
```rust
// File: build.rs
fn main() {
    #[cfg(windows)]
    {
        let mut res = winres::WindowsResource::new();
        res.set_icon("data/icons/zenomen.ico");
        res.set("ProductName", "ZenOmen");
        res.set("FileDescription", "ZenOmen OMEN/Victus Control Center");
        res.set("LegalCopyright", "Copyright (c) 2026 ZenOmen Project");
        res.set("OriginalFilename", "zenomen.exe");
        res.set_manifest(r#"
<assembly xmlns="urn:schemas-microsoft-com:asm.v1" manifestVersion="1.0">
  <assemblyIdentity version="1.0.0.0" name="ZenOmen.App"/>
  <trustInfo xmlns="urn:schemas-microsoft-com:asm.v3">
    <security>
      <requestedPrivileges>
        <requestedExecutionLevel level="asInvoker" uiAccess="false"/>
      </requestedPrivileges>
    </security>
  </trustInfo>
  <application xmlns="urn:schemas-microsoft-com:asm.v3">
    <windowsSettings>
      <dpiAware xmlns="http://schemas.microsoft.com/SMI/2005/WindowsSettings">true/pm</dpiAware>
      <dpiAwareness xmlns="http://schemas.microsoft.com/SMI/2016/WindowsSettings">PerMonitorV2, PerMonitor</dpiAwareness>
    </windowsSettings>
  </application>
</assembly>
"#);
        if let Err(e) = res.compile() {
            eprintln!("Warning: Failed to compile Windows resource: {}", e);
        }
    }
}
```

## 4. Section 10: Documentation Deliverables

The implementation wave establishes and updates the following formal specifications:

### 4.1 Architecture Documentation (`docs/architecture/`)
1. **`docs/architecture/CROSS_PLATFORM_ARCHITECTURE.md`**: Overall system topology, domain contracts, boundary separation between UI, Worker, Hardware Provider, and IPC Daemon.
2. **`docs/architecture/WINDOWS_HARDWARE.md`**: Detailed mapping of Windows telemetry engines (Win32, DXGI 1.3, PDH, WMI) and error-isolation principles.
3. **`docs/architecture/HP_WMI_PROTOCOL.md`**: Protocol specification for `hpqBIntM` (`5FB7F034-2C63-45E9-BE91-3D44E2C707E4`), query `0x20008` & `0x20009` commands, return buffers, and board profile matching.
4. **`docs/architecture/IPC_SECURITY.md`**: Threat model and implementation details for Linux D-Bus/Polkit vs Windows Named Pipe DACL & `WTSGetActiveConsoleSessionId` session isolation.

### 4.2 Architecture Decision Records (`docs/decisions/`)
1. **`docs/decisions/ADR-001-ui-framework.md`**: Preserves Slint 1.18.1 for active production; establishes GPUI-CE migration path under `src/ui/`.
2. **`docs/decisions/ADR-002-windows-hardware-interface.md`**: Decision to interface HP BIOS directly via WMI `hpqBIntM` rather than proprietary WinRing0 or third-party ring-0 drivers.
3. **`docs/decisions/ADR-003-windows-service-security.md`**: Restricting Windows Hardware Service named pipe with explicit DACL (`LocalSystem`, `Builtin Administrators`, `Interactive Users`) and session verification.
4. **`docs/decisions/ADR-004-cross-platform-ui.md`**: UI platform abstraction strategy decoupling view presentation from core hardware worker.

### 4.3 Testing and Handoff Guides (`docs/testing/`)
1. **`docs/testing/WINDOWS_TEST_MATRIX.md`**: Matrix of verified Windows builds (10 22H2 19045, 11 24H2 26100), hardware models, and automated test steps.
2. **`docs/testing/HP_BOARD_VALIDATION.md`**: Step-by-step physical verification protocol for onboarding new OMEN/Victus motherboard profiles safely without risk of firmware bricking.
3. **`docs/testing/GEMINI_TESTING_HANDOFF.md`**: Instructions for external validation agents and regression reviewers.

## 5. Section 11: Final Acceptance Criteria Verification Matrix

| # | Acceptance Criterion | Verification Method | Expected Result |
|---|:---|:---|:---|
| **1** | The same GPUI application runs on Linux, Windows 10 and Windows 11. | Execute GUI binary on all 3 target OSes. | Window opens, renders telemetry graphs, responds to input without platform panic. |
| **2** | Windows 10 22H2 and selected Windows 11 releases tested. | Run automated test runner on Win10 (19045) and Win11 (26100). | All native Win32/DXGI/PDH calls return valid metric structures. |
| **3** | CPU, RAM, GPU and battery telemetry work through native Windows interfaces. | Run `tests/windows_telemetry_tests.rs`. | Accurate utilization %, memory bytes, VRAM, and battery percentage reported. |
| **4** | Missing sensors shown as unavailable, not fabricated. | Run sensor enumeration on system without dGPU / secondary fan. | `SensorStatus::Unavailable` or `None` returned; zero fabricated zero values. |
| **5** | HP OMEN/Victus fan, power and RGB work on verified board profiles. | Execute `apply_preset()` and `apply_rgb_profile()` on verified board ID. | Firmware applies fan curve / RGB zone hex; hardware service logs verified success. |
| **6** | Windows hardware writes go through a restricted service. | Attempt hardware mutation directly from non-elevated GUI process. | GUI has no direct WMI write access; request routes through Named Pipe IPC. |
| **7** | No arbitrary WMI payload or hardware path can be supplied by GUI. | Fuzz Named Pipe client with arbitrary WMI command bytes. | Service `authorize_mutation()` rejects invalid enum IDs and out-of-range payloads. |
| **8** | Linux D-Bus and systemd security concerns resolved. | Inspect `com.zenomen.Hardware1.service` and `zenomen-hw.service`. | Service uses `SystemdService=`, sandboxed `ReadWritePaths`, and non-destructive configs. |
| **9** | All existing concerns fixed or documented as hardware limitations. | Audit against all 334 lines of `CONCERNS.md`. | Every concern reconciled, verified by unit/integration tests or marked limitation. |
| **10**| Windows and Linux installers support clean install, upgrade and removal. | Run MSI install/uninstall cycle and `.deb` dpkg install/purge cycle. | Service starts on install, stops on uninstall, zero orphaned background processes. |
| **11**| Both platform CI matrices pass. | Run full CI workflow across Ubuntu and Windows runners. | 100% green build status, zero test failures, zero clippy warnings. |
| **12**| Gemini completes independent regression reviews. | Review git diff against codebase map and architecture invariants. | Zero regression findings, strict adherence to architectural seams. |
| **13**| The seven codebase maps accurately describe the finished implementation. | Inspect `.planning/codebase/*.md` against HEAD commit. | Codebase maps reflect accurate line numbers, features, modules, and dependencies. |
| **14**| Final release is tagged only after entire release matrix passes. | Evaluate release gate script before tagging `v1.0.0`. | All automated tests, soak tests, and physical hardware gates verified green. |
