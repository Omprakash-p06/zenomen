# Plan 06-02: Cross-Platform Domain Contracts & Provider Seams

## Objective
Refactor domain contracts and sensor registry abstractions to be strictly cross-platform and root-isolated. Add explicit battery metrics to `TelemetrySnapshot`, eliminate test root leakage to the host `/sys`, align fan control discovery predicates, and resolve the history window unit duration mismatch.

## User-Facing Impact
- **Real Battery Information**: The Overview dashboard displays actual battery percentage and AC charging status.
- **Accurate History Duration**: Selecting "60s" or "300s" in Settings displays exactly 60 or 300 seconds of telemetry history regardless of whether polling is set to 1000ms or 2000ms.
- **Reliable Hardware Controls**: The UI never offers a fan control mode that subsequently fails because discovery and daemon predicates disagree.

---

### Step 2: Linux Battery Telemetry Sampling
1. **Sysfs Reader in `src/hardware/linux/provider.rs`**:
   Add helper `sample_battery(root: &Path) -> (Option<u8>, Option<bool>, Option<u32>)`:
   - Enumerate `/sys/class/power_supply/BAT*`.
   - Read `capacity` → parse `u8` (clamped 0..=100).
   - Read `status` → `"Charging"` maps to `Some(true)`, `"Discharging"` / `"Full"` / `"Not charging"` to `Some(false)`.
   - Read `time_to_empty_now` or `time_to_full_now` (if exposed by ACPI) → convert microseconds to seconds.
   - If no battery exists or reading fails, return `(None, None, None)`.
2. **Wire to Snapshot**:
   Populate `snapshot.battery_percent`, `snapshot.battery_charging`, and `snapshot.battery_remaining_seconds` in `LinuxHardwareProvider::sample()`.

### Step 3: Root Isolation in Capability Detection

2. **Update `src/hardware/rgb.rs:33-53`**:
   Ensure `detect_rgb_interface(root: &Path)` prefixes all checked paths (`/sys/devices/platform/hp-wmi`, `/sys/class/leds`) with `root`.
3. **Align Fan Acceptance Predicate in `src/hardware/registry.rs:256-315`**:
   In `resolve_fans()`, only set `has_fan_control = true` if the controlling hwmon device driver is verified as `"hp_wmi"` or `"hp"` (matching `src/service/backend.rs:77-115`). A generic or non-HP hwmon device with `pwm1_enable` must NOT be flagged as controllable HP fan hardware.

### Step 4: Fix History Window Duration Conversion
1. **Sample Math in `src/core/telemetry.rs:20-60`**:
   ```rust
   impl TelemetryHistory {
       pub fn new_with_duration(duration_seconds: u32, interval_ms: u64) -> Self {
           let capacity = (duration_seconds as u64 * 1000 / interval_ms.max(100)).max(10) as usize;
           Self {
               capacity,
               duration_seconds,
               samples: VecDeque::with_capacity(capacity),
               cached_svg_paths: None,
           }
       }

       pub fn update_interval(&mut self, interval_ms: u64) {
           let new_capacity = (self.duration_seconds as u64 * 1000 / interval_ms.max(100)).max(10) as usize;
           self.capacity = new_capacity;
           while self.samples.len() > self.capacity {
               self.samples.pop_front();
           }
           self.cached_svg_paths = None;
       }
   }
   ```
2. **Command Handling in `src/core/worker.rs:156-205`**:
   When receiving `AppCommand::SetHistoryWindow(seconds)`:
   - Call `history.set_duration(seconds, current_interval_ms)`.
   - When receiving `AppCommand::SetPollingInterval(ms)`: call `history.update_interval(ms)`.
   - This ensures selecting "120s" consistently displays 120 seconds of graph data, whether polling occurs at 500ms, 1000ms, or 2000ms.
