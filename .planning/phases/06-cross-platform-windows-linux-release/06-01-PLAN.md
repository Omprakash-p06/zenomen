# Plan 06-01: Linux Hardening & Concerns Remediation

## Objective
Remediate all unresolved security vulnerabilities, technical debt, and fragile areas in the Linux subsystem documented in `.planning/codebase/CONCERNS.md`. This establishes a rock-solid, fully audited Linux foundation before introducing Windows platform modules.

## User-Facing & Security Impact
- **Privilege Separation Hardening**: Activating the D-Bus service delegates directly to systemd, preventing unconfined root processes. The root daemon's writable sysfs footprint is strictly constrained to `/sys/devices/platform/hp-wmi` and `/sys/class/hwmon`.
- **RGB Lighting Usability**: Toggling keyboard lighting back on restores the user's custom RGB colors instead of destroying their theme with blinding white light.
- **Reliable Shutdown**: ZenOmen exits promptly when running in containers, headless sessions, or environments without a desktop session D-Bus.
- **Configuration Integrity**: Toggling autostart preserves custom `.desktop` keys instead of deleting user modifications.

## Detailed Implementation Steps

### Step 1: D-Bus Activation & Systemd Sandboxing Hardening
1. **D-Bus Service Activation**:
   Edit `data/dbus/com.zenomen.Hardware1.service`:
   ```ini
   [D-BUS Service]
   Name=com.zenomen.Hardware1
   Exec=/usr/bin/zenomen-hw
   User=root
   SystemdService=zenomen-hw.service
   ```
2. **Systemd Unit Sandboxing**:
   Edit `data/systemd/zenomen-hw.service`:
   Under `[Service]`, add restricted write paths so that even as root, arbitrary sysfs and filesystem writes outside HP WMI and hwmon are blocked by the kernel mount namespace:
   ```ini
   ProtectSystem=strict
   ProtectHome=true
   ProtectKernelTunables=true
   ProtectControlGroups=true
   ReadWritePaths=-/sys/devices/platform/hp-wmi -/sys/class/hwmon
   ```
3. **Embedded System Integration**:
   Verify `src/desktop/system_integration.rs` embeds the updated unit file and that `install_system_integration()` places it in `/etc/systemd/system/zenomen-hw.service`.

### Step 2: Non-Destructive RGB Enable/Disable
1. **Contract State**:
   In `src/service/contract.rs:40-50`, add a field to track the last configured non-empty profile:
   ```rust
   pub struct HardwareService {
       backend: Arc<dyn HardwareBackendTrait>,
       polkit: PolkitVerifier,
       last_active_rgb_profile: Arc<Mutex<Option<RgbProfile>>>,
   }
   ```
2. **Method Implementation**:
   In `SetRgbEnabled`:
   - When `enabled == false`: Query current colors, store in `last_active_rgb_profile`, and apply `#000000` (off) to all zones.
   - When `enabled == true`: If `last_active_rgb_profile` has a cached profile, restore that profile. If none is cached, default to white (`#FFFFFF`).
3. **Client Consistency**:
   In `src/service/client.rs`:
   Route `apply_rgb_profile` and `set_rgb_enabled` through `connect_service()` instead of raw `connect()`, ensuring offline daemon errors produce the same user-friendly message (`"Hardware control daemon is not active. Run 'sudo systemctl start zenomen-hw'"`).

### Step 3: Session D-Bus Absence Shutdown Safety
1. **Channel Ownership in `src/main.rs`**:
   In `src/main.rs:77-100`:
   ```rust
   let (action_sender, action_receiver) = mpsc::sync_channel::<DesktopAction>(16);
   let single_instance = ensure_single_instance(action_sender.clone());
   let _session_conn = match single_instance {
       SingleInstanceResult::Primary(conn) => {
           let _ = register_tray(&conn, action_sender);
           Some(conn)
       }
       SingleInstanceResult::AlreadyRunning => {
           return Ok(());
       }
       SingleInstanceResult::Disabled(e) => {
           tracing::warn!(error = %e, "running in standalone mode without session D-Bus");
           None
       }
   };
   // CRITICAL: Drop main's action_sender clone so receiver hangs do not occur
   // when single_instance is Disabled. The only sender left will be inside the window callbacks.
   drop(action_sender);
   ```
2. **Thread Join**:
   In `src/main.rs:270-280`, when the window closes and UI callbacks drop their sender, `action_receiver` cleanly disconnects, allowing `desktop_action_thread.join()` to terminate immediately without hanging.

### Step 4: Non-Destructive Desktop Autostart Toggle
1. **Autostart File Management in `src/desktop/autostart.rs`**:
   - `enable_autostart(exec_path)`: If `~/.config/autostart/zenomen.desktop` exists, parse existing lines. If `Hidden=true` or `X-GNOME-Autostart-enabled=false` is present, update them to `Hidden=false` / `X-GNOME-Autostart-enabled=true`. If the file does not exist, create it with the resolved absolute binary path:
     ```ini
     [Desktop Entry]
     Type=Application
     Name=ZenOmen
     Comment=Hardware control center for HP OMEN laptops
     Exec=/usr/bin/zenomen --minimized
     Icon=zenomen
     Terminal=false
     Categories=Utility;
     X-GNOME-Autostart-enabled=true
     ```
   - `disable_autostart()`: Instead of `fs::remove_file`, read the desktop entry and set `Hidden=true` and `X-GNOME-Autostart-enabled=false`, writing atomically via a temporary file. This preserves custom user additions (e.g. environment flags or window manager hints).
   - `is_autostart_enabled()`: Return `true` only if the file exists AND neither `Hidden=true` nor `X-GNOME-Autostart-enabled=false` is present.

### Step 5: Dynamic System Clock Tick Calculation
1. **Benchmark Math in `src/core/benchmark.rs`**:
   Replace the hardcoded `USER_HZ: f64 = 100.0` constant:
   ```rust
   fn get_clock_ticks_per_second() -> f64 {
       #[cfg(target_os = "linux")]
       {
           // SAFETY: sysconf with _SC_CLK_TCK (2) is safe and re-entrant
           let ticks = unsafe { libc::sysconf(libc::_SC_CLK_TCK) };
           if ticks > 0 {
               return ticks as f64;
           }
       }
       100.0 // Documented fallback
   }
   ```
   Use `get_clock_ticks_per_second()` in `cpu_percent_between` to ensure CPU percentages are strictly accurate on kernels configured with 250 Hz or 1000 Hz timers.
