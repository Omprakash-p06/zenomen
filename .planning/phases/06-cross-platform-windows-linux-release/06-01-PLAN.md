# Plan 06-01: Linux Concerns & Security Remediation

## Objective
Remediate all unresolved security vulnerabilities, technical debt, and fragile areas in the Linux codebase as documented in `.planning/codebase/CONCERNS.md` and Section 6 of the cross-platform specification. This establishes an audited, rock-solid Linux baseline before introducing Windows native code.

## Codebase Map References
- `CONCERNS.md`: § 6.1 (Tech debt), § 6.2 (Known bugs), § 6.3 (Security), § 6.4 (Performance).
- `ARCHITECTURE.md`: Privilege boundary and system integration.

## Detailed Implementation Tasks

### Task 1: Systemd Service Sandboxing & D-Bus Activation Binding
1. **D-Bus Service Activation**:
   Update `data/dbus/com.zenomen.Hardware1.service`:
   ```ini
   [D-BUS Service]
   Name=com.zenomen.Hardware1
   Exec=/usr/bin/zenomen-hw
   User=root
   SystemdService=zenomen-hw.service
   ```
2. **Systemd Sandboxing**:
   Update `data/systemd/zenomen-hw.service`:
   ```ini
   [Unit]
   Description=ZenOmen Privileged Hardware Control Service
   Documentation=https://github.com/Omprakash-p06/zenomen
   After=network.target

   [Service]
   Type=dbus
   BusName=com.zenomen.Hardware1
   ExecStart=/usr/bin/zenomen-hw
   Restart=on-failure
   RestartSec=5s
   ProtectSystem=strict
   ProtectHome=true
   ProtectKernelTunables=true
   ProtectControlGroups=true
   ReadWritePaths=-/sys/devices/platform/hp-wmi -/sys/class/hwmon
   PrivateTmp=true

   [Install]
   WantedBy=multi-user.target
   ```
3. **Synchronize System Integration**:
   Verify `src/desktop/system_integration.rs` embeds the updated unit files and installs them to `/usr/share/dbus-1/system-services/` and `/etc/systemd/system/`.

### Task 2: Non-Destructive RGB Enable/Disable State Preservation
1. **Contract Cache in `src/service/contract.rs`**:
   In `HardwareService`:
   - Add field `last_active_rgb_profile: Arc<Mutex<Option<RgbProfile>>>`.
   - In `SetRgbEnabled(enabled: bool)`:
     - When `enabled == false`: Cache current active profile, write all zones `#000000` (off).
     - When `enabled == true`: If `last_active_rgb_profile` contains a profile, restore it. If none is cached, default to white (`#FFFFFF`).
2. **Client Error Consistency in `src/service/client.rs`**:
   Route `apply_rgb_profile` and `set_rgb_enabled` through `connect_service()` instead of raw `connect()`, ensuring offline daemon errors produce the standard message:
   `"Hardware control daemon is not active. Run 'sudo systemctl start zenomen-hw'"`

### Task 3: Session D-Bus Absence Shutdown Safety
1. **Channel Dropping in `src/main.rs:77-100`**:
   In `main()`:
   ```rust
   let (action_sender, action_receiver) = mpsc::sync_channel::<DesktopAction>(16);
   let single_instance = ensure_single_instance(action_sender.clone());
   let _session_conn = match single_instance {
       SingleInstanceResult::Primary(conn) => {
           let _ = register_tray(&conn, action_sender);
           Some(conn)
       }
       SingleInstanceResult::AlreadyRunning => return Ok(()),
       SingleInstanceResult::Disabled(e) => {
           tracing::warn!(error = %e, "running in standalone mode without session D-Bus");
           None
       }
   };
   // CRITICAL FIX: Explicitly drop main's sender clone
   drop(action_sender);
   ```
   When the window closes, all senders in UI callbacks are dropped, allowing `action_receiver` to disconnect and `desktop_action_thread.join()` to terminate immediately.

### Task 4: Non-Destructive Autostart Lifecycle
1. **Desktop Entry Modification in `src/desktop/autostart.rs`**:
   - `enable_autostart(exec_path)`: If desktop file exists, parse existing lines; change `Hidden=true` to `Hidden=false` and `X-GNOME-Autostart-enabled=false` to `true`. If absent, create with `/usr/bin/zenomen --minimized`.
   - `disable_autostart()`: Instead of `fs::remove_file`, set `Hidden=true` and `X-GNOME-Autostart-enabled=false`, writing atomically via temp file.
   - `is_autostart_enabled()`: Return `true` only if file exists and neither `Hidden=true` nor `X-GNOME-Autostart-enabled=false` is present.

### Task 5: Dynamic System Clock Tick Math
1. **Benchmark Math in `src/core/benchmark.rs:142-145`**:
   Replace hardcoded `USER_HZ = 100.0` with:
   ```rust
   fn get_clock_ticks_per_second() -> f64 {
       #[cfg(target_os = "linux")]
       {
           let ticks = unsafe { libc::sysconf(libc::_SC_CLK_TCK) };
           if ticks > 0 {
               return ticks as f64;
           }
       }
       100.0
   }
   ```

### Task 6: Atomic Diagnostics Export Durability
1. **Temp Path Collisions in `src/core/diagnostics.rs:144-160`**:
   Use monotonic counter and PID in temp filename:
   ```rust
   static EXPORT_SEQ: AtomicU64 = AtomicU64::new(0);
   let seq = EXPORT_SEQ.fetch_add(1, Ordering::Relaxed);
   let temp_path = target_path.with_extension(format!("tmp.{}.{}", std::process::id(), seq));
   ```
   Open file, write JSON buffer, call `file.sync_all()`, and atomically rename to `target_path`.
