# Plan 06-04: Windows Hardware Control Service & Named-Pipe IPC

## Objective
Implement the Windows privileged hardware service (`zenomen-hw.exe`), secure local named-pipe IPC layer (`\\.\pipe\ZenOmen.Hardware.v1`), and HP BIOS WMI mailbox driver. This enables safe, verified fan speed, power profile, and 4-zone RGB control on Windows 10/11 while keeping the GUI process unprivileged.

## User-Facing & Security Impact
- **Security Boundary**: The GUI runs without administrator rights. Hardware control is brokered through an elevated Windows service that only allows predefined, strongly typed commands.
- **Hardware Safety**: No firmware writes occur unless the laptop's motherboard product ID is recognized in the board profile catalogue.
- **Consistent UX**: Fan modes (Auto/Max), ACPI performance profiles, and RGB lighting work identically on Windows and Linux.

## Detailed Implementation Steps

### Step 1: Named Pipe IPC & Security Descriptor (`src/service/windows/pipe.rs`)
1. **Pipe Configuration**:
   - Pipe Name: `\\.\pipe\ZenOmen.Hardware.v1`
   - Buffer size: 65,536 bytes (64 KB).
   - Timeouts: 30,000 ms (30 seconds) on connect/read/write.
2. **Explicit DACL Construction**:
   Build security descriptor with `InitializeSecurityDescriptor`:
   - Allow `GENERIC_ALL` to `LocalSystem` (SID `S-1-5-18`) and `Built-in Administrators` (SID `S-1-5-32-544`).
   - Allow `GENERIC_READ | GENERIC_WRITE` to `Interactive Users` (SID `S-1-5-4`).
   - Deny `Network Logon` (SID `S-1-5-2`) explicitly.
3. **Session Authentication on Client Connect**:
   When `ConnectNamedPipe` succeeds:
   - Call `ImpersonateNamedPipeClient(pipe_handle)`.
   - Call `OpenThreadToken(GetCurrentThread(), TOKEN_QUERY, TRUE, &mut token)`.
   - Call `GetTokenInformation(token, TokenSessionId, ...)` to extract caller `SessionId`.
   - Call `RevertToSelf()`.
   - Call `WTSGetActiveConsoleSessionId()`. If caller `SessionId != ActiveConsoleSessionId`, reject client and close pipe handle immediately.

### Step 2: Protocol JSON-RPC Serialization
1. **Request & Response Enums**:
   Mirror the Linux D-Bus contract:
   ```rust
   #[derive(Serialize, Deserialize, Debug)]
   pub enum HardwareRequest {
       GetCapabilities,
       GetFanStatus,
       SetFanMode { mode: String },
       GetPowerProfiles,
       GetPowerProfile,
       SetPowerProfile { profile: String },
       ApplyPreset { preset: String },
       ApplyRgbProfile { profile_json: String },
       SetRgbEnabled { enabled: bool },
   }

   #[derive(Serialize, Deserialize, Debug)]
   pub enum HardwareResponse {
       Capabilities(String),
       FanStatus { mode: String, rpms: Vec<u32> },
       Confirmed(String),
       PresetResult(String),
       Error { code: String, message: String },
   }
   ```
2. **Client Implementation in `src/service/client.rs`**:
   For Windows builds (`cfg(target_os = "windows")`), replace zbus client calls with blocking named-pipe read/write operations with connection caching and timeout detection.

### Step 3: HP BIOS WMI Mailbox Driver (`src/service/windows/wmi_hp.rs`)
1. **WMI Class & Method**:
   Connect to `ROOT\WMI` and bind `hpqBIntM`.
   HP BIOS WMI GUID: `5FB7F034-2C63-45E9-BE91-3D44E2C707E4`.
2. **Command Marshaling**:
   - `0x10`: Query physical fan count.
   - `0x11`: Query fan RPM array (CPU fan, GPU fan).
   - `0x26`: Query Max fan status (`0` = Auto, `1` = Max).
   - `0x27`: Set Max fan mode (`0` = Auto, `1` = Max).
   - `0x1A`: Query/Set ACPI performance profile.
   - `0x20009`: Apply 4-zone RGB keyboard lighting payload (24-byte RGB payload).
3. **Verified Writes & Read-Back**:
   After writing fan mode or power profile, execute read query with exponential backoff (up to 3 retries over 500ms). If the read-back value does not match the requested value, return `VERIFICATION_FAILED` error.

### Step 4: Board Profile Catalogue (`src/service/windows/board_profile.rs`)
1. **Catalogue Structure**:
   ```rust
   pub struct BoardProfile {
       pub board_id: &'static str,
       pub marketing_name: &'static str,
       pub fan_count: u32,
       pub has_fan_max: bool,
       pub has_performance_modes: bool,
       pub rgb_variant: Option<&'static str>,
   }
   ```
2. **Identification via WMI**:
   Query `Win32_BaseBoard.Product`. If product ID matches known OMEN (e.g. `"88F8"`, `"8A24"`) or Victus board, enable supported features. If unknown, report `has_fan_control = false`, preventing accidental writes to unsupported motherboards.

### Step 5: Windows Service Lifecycle & Management
1. **Dispatcher in `src/service/windows/service.rs`**:
   Implement service main using `StartServiceCtrlDispatcherW`.
   Register handler via `RegisterServiceCtrlHandlerExW`.
   Handle `SERVICE_CONTROL_STOP` and `SERVICE_CONTROL_SHUTDOWN` by signaling a cancellation token that closes the named pipe and unblocks listener threads.
2. **CLI Commands in `src/bin/zenomen-hw.rs`**:
   Support `--install-service` and `--uninstall-service` using SCM APIs (`OpenSCManagerW`, `CreateServiceW`, `DeleteService`).
