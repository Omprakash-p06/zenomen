# Plan 06-04: Windows Hardware Control Service & Named-Pipe IPC

## Objective
Implement the Windows privileged hardware service (`zenomen-hw.exe`) and secure named-pipe IPC layer (`\\.\pipe\ZenOmen.Hardware.v1`), allowing the unprivileged GUI to request verified fan, power profile, and RGB changes via the HP BIOS WMI mailbox.

## Tasks

### Task 1: Named Pipe IPC Architecture
- In `src/service/windows/pipe.rs`:
  - Implement named pipe server (`CreateNamedPipeW`) listening on `\\.\pipe\ZenOmen.Hardware.v1`.
  - Apply custom security descriptor (DACL) restricting connection to the interactive logon session (`GetNamedPipeClientSessionId`).
  - Implement JSON-RPC protocol framing with 30s timeout deadlines and 64KB message limits.
  - Implement blocking named pipe client in `src/service/client.rs` when compiling on Windows.

### Task 2: HP BIOS WMI Mailbox Driver
- In `src/service/windows/wmi_hp.rs`:
  - Connect to WMI `root\wmi` and locate `hpqBIntM` using `HPWMI_BIOS_GUID` (`5FB7F034-2C63-45e9-BE91-3D44E2C707E4`).
  - Implement command marshaling for:
    - Fan mode: Query thermal status, set Auto / Max mode.
    - Power profiles: Query and set ACPI performance profiles.
    - 4-zone RGB: Query lighting capabilities and apply zone colors.
  - Enforce board profile catalogue: verify system board ID from DMI/WMI before allowing mutations.

### Task 3: Windows Service Dispatcher
- In `src/service/windows/service.rs` and `src/bin/zenomen-hw.rs`:
  - Wire Windows Service Control Manager entry point (`StartServiceCtrlDispatcherW`).
  - Handle `SERVICE_CONTROL_STOP` and `SERVICE_CONTROL_SHUTDOWN` cleanly.
  - Add CLI arguments for service installation and removal (`zenomen-hw --install-service`, `--uninstall-service`).

## Verification
- `cargo check --target x86_64-pc-windows-msvc --bin zenomen-hw`
- Protocol unit tests in `tests/windows_service_tests.rs` (exercising serialization, payload boundaries, and mock pipe streams)
