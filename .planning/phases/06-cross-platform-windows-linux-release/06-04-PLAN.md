# Plan 06-04: Windows Hardware Control Service & Named-Pipe IPC

## Objective
Implement the Windows privileged hardware service (`zenomen-hw.exe`), secure local named-pipe IPC layer (`\\.\pipe\ZenOmen.Hardware.v1`), and HP BIOS WMI mailbox driver matching the exact module hierarchy and function signatures in Sections 4.1, 4.2, and 5.2 of the specification.

## Codebase Map References
- `ARCHITECTURE.md`: Privilege boundary, D-Bus/IPC split, and verified sysfs writes.
- `INTEGRATIONS.md`: System bus contracts and hardware service lifecycle.
- `CONVENTIONS.md`: Error types (`HardwareControlError`), PascalCase structs, and bounded message framing.

---

## Detailed Implementation Tasks

### Task 1: Windows Service Module Layout
Create `src/service/windows/`:
- `mod.rs`: Re-exports server, client, and lifecycle modules.
- `server.rs`: Service loop and request dispatch.
- `client.rs`: Unprivileged GUI named-pipe client.
- `pipe.rs`: Win32 named-pipe creation, framing, and I/O.
- `security.rs`: DACL construction and session authentication.
- `authorization.rs`: Request validation and board permission gates.
- `protocol.rs`: Strongly typed request/response framing.
- `lifecycle.rs`: Windows Service Control Manager (SCM) integration.
- `hp_wmi.rs`: HP BIOS WMI mailbox execution driver.
- `profiles.rs`: Verified board profile catalogue.

### Task 2: Named Pipe IPC & DACL Security (`pipe.rs`, `security.rs`)
Implement:
1. `pub fn create_server_pipe() -> Result<HANDLE, HardwareControlError>`:
   Calls `CreateNamedPipeW` with `\\.\pipe\ZenOmen.Hardware.v1`:
   - Flags: `PIPE_ACCESS_DUPLEX | FILE_FLAG_FIRST_PIPE_INSTANCE | FILE_FLAG_OVERLAPPED`.
   - Mode: `PIPE_TYPE_MESSAGE | PIPE_READMODE_MESSAGE | PIPE_WAIT`.
   - Max Instances: 4. Buffer: 65,536 bytes (64 KB). Timeout: 30,000 ms.
2. `pub fn build_pipe_security_descriptor() -> Result<SECURITY_ATTRIBUTES, HardwareControlError>`:
   Initializes `SECURITY_DESCRIPTOR`:
   - Sets DACL allowing `GENERIC_ALL` to `LocalSystem` (`S-1-5-18`) and `Builtin Administrators` (`S-1-5-32-544`).
   - Allows `GENERIC_READ | GENERIC_WRITE` to `Interactive Users` (`S-1-5-4`).
   - Denies `Network Logon` (`S-1-5-2`) explicitly.
3. `pub fn verify_client_session(pipe: HANDLE) -> Result<(), HardwareControlError>`:
   - Calls `ImpersonateNamedPipeClient(pipe)`.
   - Calls `OpenThreadToken` to retrieve client token.
   - Extracts `TokenSessionId` via `GetTokenInformation`.
   - Calls `RevertToSelf()`.
   - Verifies `caller_session_id == WTSGetActiveConsoleSessionId()`. If caller is from another session or remote terminal, closes connection immediately.
4. `pub fn read_frame(pipe: HANDLE) -> Result<Vec<u8>, HardwareControlError>` & `write_frame`:
   Enforces 4-byte big-endian length prefix and max 64 KB payload.

### Task 3: Typed Request Protocol & Authorization (`protocol.rs`, `authorization.rs`)
Implement:
1. Strict `HardwareRequest` and `HardwareResponse` enums matching the Linux contract:
   ```rust
   #[derive(Serialize, Deserialize, Debug)]
   pub enum HardwareRequest {
       GetCapabilities,
       GetFanStatus,
       SetFanMode { mode: String },
       GetPowerProfiles,
       GetPowerProfile,
       SetPowerProfile { profile: String },
       ApplyPreset { preset: String },
       ApplyRgbProfile { profile_json: String },
       SetRgbEnabled { enabled: bool },
   }
   ```
2. `pub fn authorize_mutation(req: &HardwareRequest, board: &BoardProfile) -> Result<(), HardwareControlError>`:
   - Validates that requested fan mode (`"Auto"`, `"Max"`) is supported by the board profile.
   - Validates that requested power profile is in the board's ACPI profile list.
   - Rejects unknown commands and malformed RGB JSON before any WMI invocation.

### Task 4: HP BIOS WMI Mailbox Driver (`hp_wmi.rs`, `profiles.rs`)
1. **WMI Connection in `hp_wmi.rs`**:
   - `pub fn connect_hp_wmi() -> Result<HpWmiConnection, HardwareControlError>`:
     Connects to `ROOT\WMI` and verifies presence of class `hpqBIntM`.
     Uses GUID `5FB7F034-2C63-45E9-BE91-3D44E2C707E4`.
2. **Execute HP Commands**:
   - `pub fn query_hp_capabilities() -> Result<HardwareCapabilities, HardwareControlError>`:
     Executes command `0x10` (fan count) and `0x28` (design data).
   - `pub fn query_fan_status() -> Result<(String, Vec<u32>), HardwareControlError>`:
     Executes command `0x26` (Max fan status: 0=Auto, 1=Max) and `0x11` (fan RPMs).
   - `pub fn set_fan_mode(mode: &str) -> Result<String, HardwareControlError>`:
     Translates mode to `0` (Auto) or `1` (Max) and executes command `0x27`.
     Performs exponential read-back verification (up to 3 retries over 500ms).
   - `pub fn set_performance_mode(profile: &str) -> Result<String, HardwareControlError>`:
     Translates profile to firmware byte (Default=`0x00`, Performance=`0x01`, Cool=`0x02`, Quiet=`0x03`) and executes command `0x1A`.
   - `pub fn set_rgb_profile(profile: &RgbProfile) -> Result<String, HardwareControlError>`:
     Constructs 24-byte RGB payload and invokes command `0x20009`.
3. **Board Profiles in `profiles.rs`**:
   - `pub fn resolve_board_profile(board_id: &str) -> Option<BoardProfile>`:
     Maps motherboard IDs (e.g. `"88F8"`, `"8A24"`, `"8A3E"`) to supported fan count, max fan capability, and RGB zone count.

### Task 5: SCM Lifecycle & CLI Service Commands (`lifecycle.rs`, `zenomen-hw.rs`)
1. `pub fn register_service() -> Result<(), HardwareControlError>`:
   Calls `OpenSCManagerW` and `CreateServiceW` installing `zenomen-hw.exe` as a Windows Service (`SERVICE_WIN32_OWN_PROCESS`, `SERVICE_AUTO_START`).
2. `pub fn uninstall_service() -> Result<(), HardwareControlError>`:
   Calls `OpenServiceW` and `DeleteService`.
3. `pub fn run_service() -> Result<(), HardwareControlError>`:
   Registers service main with `StartServiceCtrlDispatcherW`.
   Handles `SERVICE_CONTROL_STOP` and `SERVICE_CONTROL_SHUTDOWN` by signaling a cancellation token to close the named pipe and drain active workers.
4. CLI in `src/bin/zenomen-hw.rs`:
   Supports `--install-service` and `--uninstall-service`.
