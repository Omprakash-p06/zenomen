# Plan 04-03: Basic RGB — Detection, Presets, Safe Migration & Hardware Writes

## Context

Many HP OMEN and Victus laptops feature 4-zone RGB keyboard lighting. Over the evolution of the Linux `hp-wmi` driver, three distinct sysfs interface variants have emerged: the multi-file `four_zone` interface (`/sys/devices/platform/hp-wmi/rgb_zones/zone0{0..3}`), the monolithic `legacy` interface (`/sys/devices/platform/hp-wmi/keyboardleds`), and the modern `kernel_patch` interface (`/sys/class/leds/hp_omen::kbd_backlight/zone_colors`). Phase 4 delivers safe, verified RGB control: detecting the specific interface, validating `#RRGGBB` zone colors strictly (RGB-06), non-destructively migrating existing profiles from `~/.config/openomen/rgb/` without touching source files (RGB-05), gracefully ignoring unsupported animation attributes (RGB-07), and executing writes through the privileged `zenomen-hw` daemon with read-back verification (RGB-08).

## Objectives

1. Detect the active RGB hardware variant (`four_zone`, `legacy`, `kernel_patch`) or report honest unavailable status.
2. Implement strict `#RRGGBB` color parsing and error formatting.
3. Migrate legacy OpenOMEN profiles safely and provide default static presets (`White`, `Gaming`, `Rainbow`, `Off`).
4. Implement multi-interface sysfs writes in `zenomen-hw` with read-back verification.
5. Upgrade the `Lighting` screen with zone preview rectangles, preset selector, and power switch.
6. Provide full test coverage in `tests/rgb_tests.rs`.

## Tasks

### Task 1: RGB Hardware Detection & Types (`src/hardware/rgb.rs`, `src/service/types.rs`)
- Define `RgbInterfaceVariant`:
  ```rust
  #[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
  pub enum RgbInterfaceVariant {
      FourZone,    // /sys/devices/platform/hp-wmi/rgb_zones
      Legacy,      // /sys/devices/platform/hp-wmi/keyboardleds
      KernelPatch, // /sys/class/leds/hp_omen::kbd_backlight/zone_colors
  }
  ```
- Detect active variant in sysfs with root abstraction for testing.
- Expose variant in `HardwareCapabilities` (`has_rgb_lighting: bool`, `rgb_variant: Option<RgbInterfaceVariant>`).

### Task 2: Strict `#RRGGBB` Color Validation & Profile Schema (`src/rgb/schema.rs`)
- Parse hex color string:
  - Accepts `#RRGGBB` or `RRGGBB` (case-insensitive).
  - Rejects invalid hex characters, incorrect string length, or empty input with explicit error description (RGB-06).
  - Returns `RgbColor { r: u8, g: u8, b: u8 }` and formatted `#RRGGBB` hex string.
- Define `RgbProfile`:
  ```rust
  #[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
  pub struct RgbProfile {
      pub id: String,
      pub name: String,
      pub description: String,
      pub zones: [RgbColor; 4],
      pub unsupported_fields: Vec<String>, // Tracks animation fields: "brightness", "speed", etc. (RGB-07)
  }
  ```

### Task 3: Safe Legacy Profile Migration (`src/rgb/migration.rs`)
- Non-destructive migration engine (RGB-05):
  - Read `~/.config/openomen/rgb/*.json` files strictly in read-only mode.
  - Parse each file:
    - Extract `zones` mapping (`"0"`, `"1"`, `"2"`, `"3"`) or `colors`.
    - If valid, write migrated profile to `~/.config/zenomen/rgb/<id>.json`.
    - Never delete, overwrite, or mutate source files in `~/.config/openomen/rgb/`.
- Provide built-in static default presets:
  - `white`: `#FFFFFF` on all 4 zones.
  - `gaming`: `#FF0000` (sides) and `#0000FF` (middle).
  - `rainbow`: `#FF0000`, `#FF7F00`, `#00FF00`, `#0000FF`.
  - `off`: `#000000` on all 4 zones.

### Task 4: Privileged Hardware Writes & Verification (`src/service/backend.rs`, `src/service/contract.rs`)
- Implement `apply_rgb_hardware(&self, colors: &[RgbColor; 4]) -> Result<(), HardwareControlError>`:
  - **`FourZone`**: Write 6-character hex `colors[i].to_hex()` to `rgb_zones/zone0{i}`. Read back to verify.
  - **`Legacy`**: Write 24-character concatenated hex string to `keyboardleds`.
  - **`KernelPatch`**: Write 12 binary bytes `[r0, g0, b0, ...]` to `zone_colors`. Read back to verify.
- Wire to `com.zenomen.Hardware1`:
  - `ApplyRgbProfile(profile_json)`: verifies polkit, parses JSON, writes to hardware.
  - `SetRgbEnabled(enabled)`: if enabled, applies active profile; if disabled, writes black (`#000000`).

### Task 5: Lighting Screen UI (`ui/screens/lighting.slint`, `src/app.rs`)
- Update `ui/screens/lighting.slint`:
  - Interface variant badge (`Four-Zone`, `Legacy`, `Kernel Patch`).
  - Active profile name display.
  - 4-zone visual keyboard preview (rendering zone rectangles with active hex colors).
  - Profile selection list / buttons.
  - Lighting Power toggle button (Turn On / Turn Off).
  - Informational pill explaining that animations are deferred to v2 (RGB-07).
  - Unavailable panel when interface is absent.

### Task 6: Integration Tests (`tests/rgb_tests.rs`)
- Test hex color parsing with valid and invalid values.
- Test legacy OpenOMEN profile migration with mock directory; verify source files are untouched.
- Test mock sysfs writes across all 3 interface variants (`FourZone`, `Legacy`, `KernelPatch`).
- Test power on/off state transitions.

## Verification Criteria

- `cargo clippy --all-targets -- -D warnings` passes with 0 warnings.
- `cargo test --test rgb_tests` passes all tests.
- Invalid color strings fail gracefully with user-facing errors.
- Existing OpenOMEN files remain byte-for-byte identical after migration.
