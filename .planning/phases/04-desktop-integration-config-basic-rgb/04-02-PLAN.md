# Plan 04-02: Configuration Persistence & Settings UI

## Context

ZenOmen must remember user preferences between sessions without requiring manual re-configuration. Requirements SYS-06 and SYS-07 demand robust TOML persistence with failure tolerance: if a user or external script corrupts `~/.config/zenomen/config.toml`, the application must never crash or discard the corrupt file silently; it must create a timestamped backup copy (`config.toml.bak.<timestamp>`), fall back to safe defaults, and notify the user. Furthermore, telemetry polling intervals must be clamped to safe ranges (SYS-09) to ensure the application stays within its resource budget ($\le 0.1\%$ CPU).

## Objectives

1. Create typed `AppConfig` schema supporting general preferences, telemetry tuning, and hardware defaults.
2. Implement atomic file writing (`.tmp` + sync + rename) to guarantee file system integrity.
3. Implement corruption detection with automatic backup creation and fallback to defaults.
4. Bind persistent configuration to the Slint `Settings` screen and monitoring worker.
5. Provide comprehensive unit and integration tests.

## Tasks

### Task 1: Configuration Schema & Defaults (`src/config/schema.rs`)
- Define `AppConfig`:
  ```rust
  #[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
  pub struct AppConfig {
      pub general: GeneralConfig,
      pub telemetry: TelemetryConfig,
  }

  #[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
  pub struct GeneralConfig {
      pub theme: String, // "dark" (SYS-08)
      pub start_minimized: bool, // SYS-03
      pub close_to_tray: bool, // SYS-04
      pub autostart: bool, // SYS-02
  }

  #[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
  pub struct TelemetryConfig {
      pub history_window: usize, // 120 (30, 60, 120, 300)
      pub polling_interval_ms: u64, // 1000 (clamped 500ms..=5000ms, SYS-09)
  }
  ```
- Implement clamping helper: `polling_interval_ms.clamp(500, 5000)`.

### Task 2: Config Storage, Atomic Write & Corruption Recovery (`src/config/mod.rs`)
- Path resolution: `~/.config/zenomen/config.toml`.
- `load_or_default(path: &Path) -> (AppConfig, Option<String>)`:
  - If file does not exist, return `(AppConfig::default(), None)`.
  - If file exists:
    - Attempt to parse as TOML.
    - If valid, return `(config, None)`.
    - If deserialization fails:
      - Create backup copy: `config.toml.bak.<timestamp>`.
      - Return `(AppConfig::default(), Some(backup_path_str))`.
- `save_atomic(path: &Path, config: &AppConfig) -> Result<(), ConfigError>`:
  - Write to `path.with_extension("tmp")`.
  - Call `file.sync_all()`.
  - Atomically rename to `path`.

### Task 3: Settings UI & Core State Integration (`ui/screens/settings.slint`, `src/app.rs`)
- Expand `ui/screens/settings.slint`:
  - Add controls for "Start Minimized", "Close to Tray", and "Launch at Login" toggles.
  - Add telemetry polling interval selector (500ms, 1000ms, 2000ms).
  - Add theme indicator ("Dark (ZenOmen)").
  - Render notification banner if corrupt config was backed up.
- Wire UI callbacks to `AppCommand`:
  - `UpdateConfig(AppConfig)`: saves config atomically and applies settings to state and monitoring worker.

### Task 4: Integration Tests (`tests/config_tests.rs`)
- Test config roundtrip (save -> load -> verify identical).
- Test atomic rename behavior.
- Test corrupt config recovery: corrupt file produces `.bak.<timestamp>` and loads default config without panic.
- Test polling interval clamping to `[500, 5000]`.

## Verification Criteria

- `cargo clippy --all-targets -- -D warnings` passes with 0 warnings.
- `cargo test --test config_tests` passes all tests.
- Corrupting `config.toml` does not crash the app, creates a backup file, and resets to defaults.
