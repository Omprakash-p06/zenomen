# Plan 02-01: Linux Hardware Provider — procfs, hwmon, DRM & NVIDIA

## Objective
Implement `LinuxHardwareProvider` to sample real hardware telemetry on Linux systems via procfs (`/proc/stat`, `/proc/meminfo`, `/proc/cpuinfo`), sysfs cpufreq, dynamic DRM sysfs enumeration (supporting AMD and Intel without hardcoding `card0`), and non-blocking NVIDIA querying. Ensure absent sensors yield `None` (rendering `Unavailable`) rather than `0`, CPU delta calculation performs zero sleeps on the worker thread, and RAM math uses `MemTotal - MemAvailable`.

## Context & Design Rules
- Follow [`02-RESEARCH.md`](file:///home/omprakash/Documents/zenomen/.planning/phases/02-linux-telemetry-capability-detection/02-RESEARCH.md) specifications for Linux telemetry:
  - **CPU Utilization (MON-01, MON-02):**
    - Read `/proc/stat`. Sum jiffies: `idle_all = idle + iowait`, `system_all = system + irq + softirq`, `virtual_all = guest + guest_nice`, `total = user + nice + system_all + idle_all + steal + virtual_all`.
    - Delta calculation: `delta_total = total - prev_total`, `delta_idle = idle_all - prev_idle_all`, `utilization = 100.0 * (1.0 - delta_idle / delta_total)`.
    - Zero sleep calls inside `sample_telemetry()`! Previous jiffies must be stored in mutable state inside `LinuxHardwareProvider` across 1 Hz worker ticks.
    - Read CPU model name from `/proc/cpuinfo` `model name` line.
  - **CPU Frequency (MON-03):**
    - Read `/sys/devices/system/cpu/cpu0/cpufreq/scaling_cur_freq` (divide by 1000 for MHz). Fall back to `/proc/cpuinfo` `cpu MHz` if cpufreq sysfs is not exposed.
  - **RAM Metrics (MON-07):**
    - Read `/proc/meminfo`. Extract `MemTotal` and `MemAvailable` (in kB).
    - `total_mb = MemTotal / 1024`, `used_mb = (MemTotal - MemAvailable) / 1024`.
    - Never use `MemFree` (which ignores buffers/reclaimable cache and causes false ~95% RAM warnings).
  - **GPU Metrics (MON-05, MON-06):**
    - Dynamically scan `/sys/class/drm/card*` (match regex/prefix `card[0-9]+$`, skipping connector directories like `card1-eDP-1`).
    - Detect vendor via `device/vendor`: `0x1002` (AMD), `0x8086` (Intel), `0x10de` (NVIDIA).
    - For AMD (`amdgpu`): read utilization from `device/gpu_busy_percent`, VRAM used/total from `device/mem_info_vram_used` and `device/mem_info_vram_total`.
    - For NVIDIA: execute `nvidia-smi --query-gpu=name,utilization.gpu,temperature.gpu,memory.used,memory.total --format=csv,noheader,nounits` with a short 200ms timeout. If command fails, driver is suspended in D3cold, or missing, return `None` without blocking or erroring.
  - **Sensor Absence (MON-08):**
    - Every missing or unreadable sensor must produce `None` in `TelemetrySnapshot`, never a default of `0`.

    3. Implement `parse_proc_meminfo(content: &str) -> Option<MemorySnapshot>`:
       - Parse lines looking for `MemTotal:` and `MemAvailable:` with values in `kB`.

       - If `MemTotal` or `MemAvailable` is missing, return `None`.
    4. Implement `read_memory_snapshot() -> Result<MemorySnapshot, String>` that reads `/proc/meminfo` and calls `parse_proc_meminfo`.
  </action>

    - Handles standard Linux `/proc/meminfo` output format.
    - Returns `None` if keys are missing rather than synthesizing `0`.
