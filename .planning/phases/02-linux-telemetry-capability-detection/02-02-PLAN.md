# Plan 02-02: Capability Detection & Single Shared SensorRegistry

## Objective
Implement a single, shared `SensorRegistry` that discovers and registers canonical hardware sensor bindings across the Linux sysfs and hwmon tree. Guarantee that CPU temperature is resolved by driver and label priority (`k10temp` > `coretemp` > `acpitz`), fan tachometers are properly enumerated, and both the runtime telemetry sampler and diagnostics report reference identical sensor paths (**MON-04**, **MON-08**, **MON-12**).

## Context & Design Rules
- Follow [`02-RESEARCH.md`](file:///home/omprakash/Documents/zenomen/.planning/phases/02-linux-telemetry-capability-detection/02-RESEARCH.md):
  - **CPU Temperature Priority Matrix (MON-04):**
    - Linux `/sys/class/hwmon/hwmon*` entries can appear in arbitrary index order (`hwmon0` through `hwmonN`). Channel index or directory number must never be used.
    - Inspect `name` file for each hwmon device:
      1. `k10temp`: AMD CPU temperature. Check labels `temp*_label` for `Tctl` or `Tdie`; fall back to `temp1_input`.
      2. `coretemp`: Intel CPU temperature. Check labels `temp*_label` for `Package id 0`; fall back to `temp1_input`.
      3. `acpitz`: ACPI thermal zone fallback (`temp1_input`).
    - Parse raw millidegrees Celsius into degrees Celsius (`f32 = millidegrees / 1000.0`).
  - **Fan Sensor Discovery:**
    - Scan for `hp`, `hp-wmi`, or platform hwmon devices.
    - Discover tachometers `fan1_input`, `fan2_input`, etc. (RPM values).
    - Check presence of `pwm1_enable` or control nodes to set `has_fan_control`.
  - **ACPI Power Profiles:**
    - Check `/sys/firmware/acpi/platform_profile` and `/sys/firmware/acpi/platform_profile_choices`.
  - **Shared SensorRegistry (MON-12):**
    - The `SensorRegistry` struct is instantiated once by `LinuxHardwareProvider` on initialization and passed or made queryable by diagnostics:
      ```rust
      pub struct SensorRegistry {
          pub cpu_temp: Option<SensorDescriptor>,
          pub fans: Vec<FanSensorDescriptor>,
          pub gpus: Vec<GpuSensorDescriptor>,
      }
      ```
    - The telemetry worker reads the specific paths designated by `SensorRegistry`. Diagnostics displays the exact same sensor descriptors and drivers.
  - **Absent Sensors (MON-08):**
    - When no valid sensor matches the priority matrix, `cpu_temp` is `None`. The UI receives `None` and displays `Unavailable`.
