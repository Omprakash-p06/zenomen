# Plan 02-03: Live Charts, Refresh & History Controls, Diagnostics Report & Export

## Objective
Deliver dynamic telemetry history window controls (**MON-11**), verified on-demand manual refresh (**MON-10**), system diagnostics report generation covering OS/kernel, DMI identifiers, shared `SensorRegistry` bindings, and capabilities (**DIAG-01**), along with recent errors and snapshot readings exported to a file (**DIAG-02**). Wire `LinuxHardwareProvider` as the default runtime provider in `main.rs`.

## Context & Design Rules
- Follow [`02-RESEARCH.md`](file:///home/omprakash/Documents/zenomen/.planning/phases/02-linux-telemetry-capability-detection/02-RESEARCH.md) specifications:
  - **History Window Configuration (MON-11):**
    - `TelemetryHistory` must support dynamic resizing via `set_capacity(new_capacity: usize)`.
    - If new capacity is smaller, discard oldest entries with `pop_front()`.
    - Chart paths generated via `generate_chart_paths` must scale to the configured capacity.
    - Wire `AppCommand::SetHistoryWindow(usize)` from Slint Settings screen. Predefined options: 30s, 60s, 120s (default), 300s.
  - **On-Demand Refresh (MON-10):**
    - The worker thread uses `recv_timeout` on the command channel. When `AppCommand::RefreshTelemetry` arrives, it immediately samples without waiting for the 1s tick.
    - Verified against `LinuxHardwareProvider`.
  - **Diagnostics Detection Report (DIAG-01, DIAG-02):**
    - System info:
      - App version: `env!("CARGO_PKG_VERSION")`.
      - OS: parse `PRETTY_NAME` from `/etc/os-release`.
      - Kernel: read `/proc/sys/kernel/osrelease` or `uname`.
      - DMI Board/Chassis: read `/sys/class/dmi/id/product_name` and `/sys/class/dmi/id/sys_vendor`.
    - Sensor bindings:
      - Export detected sensor paths from `SensorRegistry` (CPU temperature sysfs path & driver, fan tachometer paths, GPU devices).
      - Guarantee that the sensors listed in diagnostics are identical to those polled by the dashboard (MON-12).
    - Capabilities:
      - Per-subsystem boolean status from `HardwareCapabilities`.
    - Readings & Errors:
      - Include latest `TelemetrySnapshot` readings and `last_sampling_error` if any.
    - Export file:
      - Function `export_diagnostics_to_file(path: &Path, report: &DiagnosticsReport) -> Result<(), std::io::Error>`.
      - Generates formatted JSON file containing all diagnostic information with no personal private data (DIAG-03 preparation).
  - **Runtime Provider Selection:**
    - In `src/main.rs`: Check `std::env::var("ZENOMEN_MOCK_SCENARIO")`. If present, use `MockHardware`. Otherwise, instantiate `LinuxHardwareProvider`.
