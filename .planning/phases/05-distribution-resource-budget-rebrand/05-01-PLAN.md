# Plan 05-01: Packaging & Release — DEB, AppImage, System Integration, Checksums

## Objective

Make ZenOmen installable. Produce a DEB and an AppImage that install the desktop entry,
systemd unit, D-Bus policy and polkit action in their correct locations, fix the systemd
unit path that currently prevents the service from starting after a package install, and
publish both artifacts with a checksum file automatically on a version tag — gated on the
quality checks that already exist in CI.

## Context & Design Rules

- Cargo Packager is the designated tool (`PROJECT.md`, Constraints). Configuration goes in
  `[package.metadata.packager]` in `Cargo.toml`; no `debian/` tree and no `postinst`
  shell scripts.
- The existing assets in `data/` are the packaging inputs and must not be duplicated.
  Only the desktop entry is missing.
- `/usr/bin` is the install prefix for both binaries. `data/systemd/zenomen-hw.service`
  currently points at `/usr/local/bin` and is wrong for every package manager.
- An AppImage cannot write `/etc` or `/usr/share`; system integration therefore ships as
  an explicit root-only command in the GUI binary, backed by `include_str!` of the same
  files the DEB installs. One source of truth, two delivery mechanisms.
- Do not add new runtime crates for packaging. Anything the release workflow needs is a
  CI-time tool.
- Existing gates in `.github/workflows/ci.yml` stay exactly as they are; the release
  workflow reuses the same commands rather than inventing a second definition of "green".

    1. Create `data/applications/zenomen.desktop`:

       ```
       Type=Application
       Name=ZenOmen
       ```

       DEB additionally gets a generated entry from Cargo Packager's `deb.desktopTemplate`;
       both must agree on `Icon=zenomen` and the `Utility` category.
    2. Fix `data/systemd/zenomen-hw.service`: change
       `ExecStart=/usr/local/bin/zenomen-hw` to `ExecStart=/usr/bin/zenomen-hw`.
       Do not touch the hardening block (`ProtectSystem`, `ReadOnlyPaths`,
       `ReadWritePaths`, `NoNewPrivileges=false`) — it matches the sysfs-only write
       surface Phase 3 delivered.
    3. Add to `Cargo.toml`:
       ```toml
       [package.metadata.packager]
       productName = "ZenOmen"
       identifier = "com.zenomen.ZenOmen"
       description = "Lightweight hardware control center for HP OMEN and Victus laptops"
       category = "Utility"
       licenseFile = "LICENSE"
       icons = [
         "data/icons/hicolor/*/apps/zenomen.png",
         "data/icons/hicolor/scalable/apps/zenomen.svg",
       ]
       outDir = "dist"
       binaries = [
         { path = "zenomen", main = true },
         { path = "zenomen-hw", main = false },
       ]
       beforePackagingCommand = "cargo build --release --bins"

       [package.metadata.packager.deb]
       depends = ["libxkbcommon0", "libfontconfig1", "libgl1", "libdbus-1-3"]

       [package.metadata.packager.deb.files]
       "data/applications/zenomen.desktop" = "/usr/share/applications/zenomen.desktop"
       "data/systemd/zenomen-hw.service" = "/usr/lib/systemd/system/zenomen-hw.service"
       "data/dbus/com.zenomen.Hardware1.conf" = "/usr/share/dbus-1/system.d/com.zenomen.Hardware1.conf"
       "data/polkit/com.zenomen.hardware.policy" = "/usr/share/polkit-1/actions/com.zenomen.hardware.policy"
       "README.md" = "/usr/share/doc/zenomen/README.md"

       [package.metadata.packager.appimage]
       bins = ["dist/zenomen", "dist/zenomen-hw"]
       ```

       `icons` takes globs or file paths, not a directory, so the two entries above are
       required as written. Adjust the exact key spelling against the Cargo Packager
       version actually used if the schema differs (`deb.files` maps a source path to a
       path inside the package root). Verify by inspecting the built `.deb` with
       `dpkg -c`.
       Add `dist/` to `.gitignore` if the existing entry does not already cover it.
  </action>

    1. Create `src/desktop/system_integration.rs`:
       - Embed the four assets with `include_str!("../../data/...")` so the AppImage needs

       - Define the fixed install targets as constants:
         `/usr/share/applications/zenomen.desktop`,
         `/usr/lib/systemd/system/zenomen-hw.service`,
         `/usr/share/dbus-1/system.d/com.zenomen.Hardware1.conf`,

       - `pub fn install() -> Result<(), SystemIntegrationError>`: refuse with a clear
         message when `geteuid() != 0`, create parent directories, write each file
         atomically (temp file in the same directory + `rename`), then run
         `systemctl daemon-reload`, `systemctl enable zenomen-hw` and
         `systemctl restart zenomen-hw`, returning the combined stderr on failure.
       - `pub fn uninstall() -> Result<(), SystemIntegrationError>`: stop and disable the
         unit, remove only the four files this command owns, reload systemd.
       - Never touch `/sys`, never accept a caller-supplied path, never shell out with a
         constructed command string (use `Command::new` with literal arguments).
       - Unit-test the path table, the non-root refusal and the atomic write helper
         against a temporary directory; keep the `systemctl` invocation behind a trait or
         an injectable runner so tests never execute it.
    2. Declare the module in `src/desktop/mod.rs`.
    3. In `src/main.rs`, before any Slint initialisation, handle
       `--install-system-integration` and `--uninstall-system-integration`: run the action,
       print the outcome to stdout/stderr and exit with 0/1. Return early so the GUI never
       starts in these modes.
    4. Add `tests/packaging_tests.rs` covering: refusal when not root (skipped when the
       suite itself runs as root), correct content of each embedded asset against the file

<threat_model>
| Threat ID | Component | Vulnerability / Attack Surface | Impact | Mitigation Strategy |
|---|---|---|---|---|
| T-05-01 | Release workflow | A compromised or mistyped workflow publishes an artifact without passing the audit gate | Users install a package with a known-vulnerable or malicious dependency | Quality gates run before packaging in the same job; packaging cannot start unless fmt, clippy, tests and `cargo audit` succeed. `permissions` is scoped to `contents: write` only. |
| T-05-02 | `--install-system-integration` | Arbitrary file write if a caller could supply paths, or a path traversal through an embedded filename | Root-owned file overwrite anywhere on the filesystem | All four destinations are compile-time constants; no caller-supplied path exists; the command refuses to run without effective UID 0. |
| T-05-03 | systemd unit installed by RootOnly command | A unit installed with a writable path or relaxed hardening lets a local user escalate | Privilege escalation to root via the daemon | The unit that ships is the reviewed asset with `ProtectSystem=strict`, `ProtectHome=true`, `ReadOnlyPaths=/` and `NoNewPrivileges=false`; the installer writes it verbatim with no substitution. |
| T-05-04 | Package payload | Untrusted DEB dependency pulling a hostile package | Compromised host libraries | `deb.depends` is a fixed, minimal list of well-known Ubuntu runtime packages; no post-install script runs, so nothing executes at `dpkg` time beyond dpkg itself. |
| T-05-05 | Release artifact integrity | A tampered download cannot be detected | User installs a modified binary | `SHA256SUMS` is published alongside the artifacts and the documented verification command is part of the install instructions. |
</threat_model>

## Verification

- `cargo fmt --all -- --check` passes.
- `cargo clippy --all-targets --all-features -- -D warnings` passes with zero warnings.
- `xvfb-run --auto-servernum cargo test --all` passes, including `tests/packaging_tests.rs`.
- `cargo packager --release --formats deb` produces a `.deb` whose `dpkg -c` listing contains `/usr/bin/zenomen`, `/usr/bin/zenomen-hw`, the desktop entry, the systemd unit, the D-Bus policy and the polkit action at the documented paths.
- `cargo packager --release --formats appimage` produces an `.AppImage` whose extracted AppDir contains both binaries and the desktop entry.
- `zenomen --install-system-integration` as non-root exits non-zero and writes nothing; the AppImage on a clean host installs the four files and leaves `zenomen-hw` active.
- `.github/workflows/release.yml` fails on a clippy warning, a failing test or an advisory, and attaches `SHA256SUMS` with both artifacts on a tag.
