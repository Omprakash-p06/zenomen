# Plan 05-02: Resource Budget — Measured, Not Asserted

## Objective

Prove the two headline numbers with measurements instead of intentions: ≤40 MB peak RSS
for the UI process across a two-hour tray session, and idle CPU at ≤0.1 % on the dashboard
and ≤0.02 % minimized. Add the missing CPU instrumentation, stop sampling hardware while
the window is hidden, record per-stage figures for both processes separately, and prove
graceful degradation with a test per absent input.

## Context & Design Rules

- The project's core value is honesty: a number that was not measured is not claimed.
  `docs/RESOURCE-BUDGET.md` records the command, the duration and the observed figures,
  and any target that could not be measured on real hardware stays explicitly unverified.
- `src/core/benchmark.rs` already reads `Rss`/`Pss`/`Private_Dirty` from
  `/proc/self/smaps_rollup` with a `/proc/self/status` fallback. Extend it; do not replace
  it, and keep the fallback.
- Measurement runs on the sampling thread or an external harness, never on the UI thread
  (PERF-03 must not regress).
- The UI process and the hardware service are reported as two separate budgets. Summing
  them is a defect, not a rounded figure.
- `panic = "abort"` is set for release builds, so a degradation path cannot rely on
  catching panics — every absence must be handled where it is read.

  <action>
    The tracer slice is one real number, produced end to end: idle CPU with the dashboard
    open, measured by the same harness that will later cover every stage.
    1. In `src/core/benchmark.rs` add:
       - `pub struct CpuSample { pub jiffies: u64, pub at: Instant }`.
       - `pub fn read_cpu_sample() -> Result<CpuSample, io::Error>` reading fields 14 and
         15 (`utime`, `stime`) from `/proc/self/stat`, skipping the `(comm)` field that may
         contain spaces or parentheses. Parse the remainder by splitting on whitespace
         after the last `)`. A malformed file is an `InvalidData` error, never a panic.
       - `pub fn cpu_percent_between(start: &CpuSample, end: &CpuSample, clock_ticks: u64) -> f64`
         returning `(delta_jiffies / clock_ticks) / elapsed_secs * 100.0`, clamped at 0
         and guarding against zero elapsed time.
       - `pub const USER_HZ: u64 = 100;` with a doc comment that it is the Linux default
         and that callers who need exactness pass a measured value.
       - `pub struct StageReport { pub stage: &'static str, pub rss_mb: f64, pub cpu_percent: f64 }`
         and `pub fn measure_stage(stage, window: Duration) -> Result<StageReport, io::Error>`
         that takes a CPU sample, sleeps `window` (blocking, so it must never be called from
         the UI thread), takes a second sample and combines it with an RSS reading.
    2. Create `scripts/measure-budget.sh`:
       - Usage: `measure-budget.sh <stage> <duration-seconds> <command...>`.
       - Starts the command, waits 3 s for warm-up, samples `/proc/<pid>/status` `VmRSS`
         and `/proc/<pid>/stat` utime+stime once per second for `<duration>`, then writes a
         summary line `stage,pid,rss_peak_mb,rss_final_mb,cpu_avg_percent,samples` to stdout
         and appends the same line to `dist/budget-<stage>.csv`.
       - Reads `CLK_TCK` via `getconf CLK_TCK` and falls back to 100.
       - Exits non-zero if the process dies before the window elapses, so a crashed run can
         never be reported as a good measurement.
    3. Run the tracer measurement: `./scripts/measure-budget.sh dashboard-open 60
       ./target/release/zenomen` under `xvfb-run` with a real or mock provider, and record
       the observed RSS and CPU in `docs/RESOURCE-BUDGET.md` under "Dashboard idle CPU".
       Target: CPU ≤ 0.1 %.
    4. Add `tests/benchmark_tests.rs` coverage for `read_cpu_sample` (succeeding, with a
       later sample having >= the earlier jiffies), `cpu_percent_between` (a known
       jiffies/elapsed pair yields the expected percentage; zero elapsed yields 0.0), and
       `measure_stage` on a short window reporting a positive RSS.
  </action>
  <acceptance_criteria>
    - `read_cpu_sample()` parses a `comm` containing spaces and parentheses without error.
    - `cpu_percent_between` returns the mathematically expected value for a known pair and 0.0 for zero elapsed time.
    - `scripts/measure-budget.sh` emits one CSV summary line for a 60-second run and exits non-zero when the target process exits early.
    - `docs/RESOURCE-BUDGET.md` contains a measured dashboard idle CPU figure with its command and window length.
  </acceptance_criteria>
  <verify>
    <automated>cargo test --test benchmark_tests</automated>
    <fails_when>non-zero exit code</fails_when>
  </verify>

<threat_model>
| Threat ID | Component | Vulnerability / Attack Surface | Impact | Mitigation Strategy |
|---|---|---|---|---|
| T-05-06 | Benchmark instrumentation | `ZENOMEN_BENCHMARK` printing process paths or sensor values into logs | Local information disclosure about the machine's hardware | Benchmark lines contain only a stage name and an RSS figure; no paths, no sensor values, no identifiers. |
| T-05-07 | Measurement harness script | Shell script interpolating an untrusted stage name or command into a path | Arbitrary file overwrite via the CSV output path | The stage name is validated against a fixed allow-list before it is used in `dist/budget-<stage>.csv`; the measured command is passed as an argument vector, never through `eval`. |
| T-05-08 | Degradation paths | A missing privileged service being treated as "allow" for a write | Silent privilege bypass or an unverified hardware write | Every absent-service case in the matrix asserts the write is refused and the sysfs file is unchanged; read-only telemetry degrades, writes do not. |
</threat_model>
